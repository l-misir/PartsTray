# 指示書B：かざぐるマウスの機能を LogiGap に追加する

あなた（Codex）への実装依頼です。**指示書A で作った `app/` の LogiGap に機能を追加**します。最後まで読んでから着手してください。
「（理由: …）」は、その指示を出す理由です。迷ったときは理由に沿うほうを選んでください。

## 0. 作業のルール

- **指示書A の §0（作業のルール）と §6（安全のための約束）は、そのまま有効**です。まず `codex/指示書A_つなぎ役.md` と、`app/` の既存コードを読んでから着手してください
- 指示書A の機能（つなぎ役）の動作を変えないでください。共通部分（トレイ、設定、ログ）を変える場合は、つなぎ役のテストが通り続けること
- 再現の元になる設定は `data/kazaguru/設定まとめ.md` にまとめてあります（元の ini は `data/kazaguru/Kazaguru.ini`）。**かざぐるマウス本体（exe・dll）のコードやリソースは使いません**。動作を再現するだけです

## 1. 背景と目的

- ユーザーは「かざぐるマウス」（フリーソフト、Windows 8 までが対応範囲）で、マウスジェスチャーなどを使っています。Windows 11 に対応していないため、**設定してある機能をすべて**このアプリで再現します
- **最優先は、右ドラッグ中に描かれる緑・赤の軌跡です。** ユーザーはこれを「らくがき」代わりに使っているので、見た目と追従性を必ず再現してください
- **かざぐるマウスには、「たまにスクロールが一切効かなくなり、再起動すると直る」という不具合があります。** 原因の推測は `設定まとめ.md` の最後の節にあります。**この不具合を構造的に起こさない設計**にしてください（§3）

## 2. 再現する機能の一覧

### 2.1 マウスジェスチャー（右ボタンを押しながら動かして離す）

| 動き | コマンド | 実行内容 |
|---|---|---|
| ← | 戻る | 対象ウィンドウに Alt+← |
| → | 進む | 対象ウィンドウに Alt+→ |
| ↑↓ | 更新 | 対象ウィンドウに F5 |
| ↓→ | 閉じる | ブラウザとエクスプローラなら Ctrl+W（タブを閉じる）。それ以外は WM_SYSCOMMAND / SC_CLOSE を対象のトップレベルウィンドウへ PostMessage |
| ↓← | 最小化 | 対象のトップレベルウィンドウへ WM_SYSCOMMAND / SC_MINIMIZE を PostMessage |

- **対象ウィンドウ**＝右ボタンを押した位置にあるウィンドウのトップレベル（GetAncestor(GA_ROOT)）
- キー入力のコマンドは、対象ウィンドウがフォアグラウンドでなければ、先にフォアグラウンドにしてから送る。SetForegroundWindow が拒否される場合への対策を入れること（例：AttachThreadInput で一時的に入力を共有する。失敗したらログに残し、何も送らない）（理由: 別のウィンドウにキーが届く事故を防ぐ）
- ブラウザの判定はプロセス名で行う：chrome.exe, msedge.exe, firefox.exe, brave.exe, vivaldi.exe, opera.exe。設定で追加できるようにする
- ジェスチャーとコマンドの対応は設定ファイルで変えられるようにする（§6）

### 2.2 ジェスチャーの動作の細部（`設定まとめ.md` の値）

| 項目 | 値・動作 |
|---|---|
| ストロークの判定 | 直前の基準点から縦か横に **10 px** 以上動いたら、大きいほうの軸の向き（↑↓←→）を 1 ストロークとする。直前のストロークと同じ向きなら追加しない。判定後は基準点を現在位置に移す。距離は物理ピクセル（DPI スケーリング前の画面座標） |
| 入力開始のタイムアウト | 右ボタンを押してから **1000 ms** 以内に最初のストロークが成立しなければ、ジェスチャーをやめて通常の右ボタン操作に戻す（§2.3） |
| 有効・無効 | その時点までのストローク列が、登録済みジェスチャーと**完全に一致**すれば有効、それ以外（未登録、途中）は無効 |
| 離したとき | ストロークが 1 つ以上あれば、有効ならコマンドを実行し、無効なら何もしない。**どちらの場合も右クリック（コンテキストメニュー）は出さない** |
| 連続実行 | ストロークが 1 つ以上ある状態で左クリックすると、その時点で有効なジェスチャーのコマンドを実行する。左ボタンの押下・解放は相手に渡さない。一度でも連続実行したら、右ボタンを離したときにはもう実行しない（`// 要確認:` 付きで実装） |
| ツールチップ | ジェスチャー中に **1000 ms** 静止したら（移動 2 px 未満）、カーソルの近くに入力中のジェスチャーを出す。例：「↓→ 閉じる」、無効なら「↓→↑ （未登録）」。動いたら消す |

### 2.3 右ボタンを相手に返す（ジェスチャーにならなかったとき）

フックは右ボタンの押下をいったん握りつぶします。ジェスチャーにならなかった場合は、元の操作として相手に届け直します。

- ストロークが 0 のまま離した → その場で右ボタンの押下と解放を SendInput で送る（通常の右クリック）
- 1000 ms たってもストロークが 0 → 右ボタンの押下を SendInput で送り、その後のイベントは素通しにする（通常の右ドラッグや長押し）。右ボタンを離したら通常状態に戻る
- 送り直す入力にも、dwExtraInfo に 0x4C474150（"LGAP"）を付ける。フックはこの印の付いた入力を素通しにする

### 2.4 ジェスチャーを始めない場所

右ボタンを押した瞬間、フックの中では判定せず、いったん握りつぶします。判定はワーカー側で行い、始めない場合は §2.3 と同じく、押下をすぐ送り直します（理由: 判定に時間がかかってもフックを止めないため）。

- **エクスプローラ（explorer.exe）のファイル一覧で、選択中の項目の上**から押した場合（理由: ファイルを右ドラッグでコピー・移動する操作を邪魔しない）。判定には UI Automation の ElementFromPoint と SelectionItemPattern.IsSelected を使う。50 ms 以内に判定できなければ「ジェスチャーを始める」とみなす。詳細表示の文字の右側の余白は、背景とみなす
- 設定の除外リスト（プロセス名）にあるアプリ。既定は空
- 機能を一時停止中
- これ以外（ブラウザ、一般のウィンドウ、タイトルバー、タスクバーボタン、デスクトップなど）では、すべてジェスチャーを有効にする

### 2.5 軌跡の描画（最優先。らくがき機能として使われる）

| 項目 | 仕様 |
|---|---|
| いつ描くか | 最初のストロークが成立した時点から描き始める。そのとき、右ボタンを押した位置からの経路も含めて描く。右ボタンを離すまで描き続け、離したら即座に消す |
| 線 | 幅 3 px（物理ピクセル）、端は丸く、アンチエイリアスあり |
| 色 | 有効なら緑 #00FF00、無効なら赤 #FF0000。**有効・無効が切り替わったら、軌跡全体を新しい色で描き直す** |
| 範囲 | 全モニター。モニターをまたいでも線がつながる。モニターごとに DPI が違っても位置がずれない |
| 追従性 | カーソルから遅れて見えないこと。入力から次の画面更新までに描く |
| 長さ | 数千〜数万点の長い軌跡（らくがき）でも、カクつきや遅延が増えないこと |
| 邪魔しない | クリックを透過し、フォーカスを奪わず、Alt+Tab やタスクバーに出ない。全画面のウィンドウより手前に出す |

実装方針（この方針を基本にしてください）：
- **モニターごとに 1 枚、透明なオーバーレイウィンドウ**を作る。拡張スタイルは WS_EX_LAYERED \| WS_EX_TRANSPARENT \| WS_EX_TOPMOST \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE
- 描画は 32bit（事前乗算アルファ）の DIB に線分を**追記していく**方式にする。更新は UpdateLayeredWindowIndirect で、**変化した矩形（prcDirty）だけ**を送る（理由: 毎回全画面を描き直すと、長い軌跡や高解像度で遅くなる）
- 色の切り替え時だけ、全体を描き直す
- 描画は UI スレッド（またはオーバーレイ専用のスレッド）で行い、フックのスレッドでは絶対に描かない
- アプリ全体を Per-Monitor DPI Aware V2 にする（app.manifest）

### 2.6 タイトルバーなどの操作

| 操作 | コマンド | 実行内容 |
|---|---|---|
| タイトルバーを Shift+左クリック | 常に最前面に表示（切り替え） | SetWindowPos で HWND_TOPMOST と HWND_NOTOPMOST を切り替える（SWP_NOMOVE \| SWP_NOSIZE \| SWP_NOACTIVATE）。音や強調表示はしない |
| タイトルバーを Ctrl+左クリック | 実行ファイルのフォルダを開く | ウィンドウのプロセスの実行ファイルパスを QueryFullProcessImageName で取り、`explorer.exe /select,"パス"` で開く |
| タイトルバーを中央クリック | ウィンドウを閉じる | WM_SYSCOMMAND / SC_CLOSE を PostMessage |
| 最小化ボタンを右クリック | 通知アイコン化 | §2.7 |

- 判定には WM_NCHITTEST を使う（HTCAPTION = タイトルバー、HTMINBUTTON = 最小化ボタン）。Chrome や Windows 11 標準アプリのように、タイトルバーを自前で描くアプリも WM_NCHITTEST には正しく答えるので、これで判定する
- **WM_NCHITTEST は別プロセスへの送信なので、フックの中では送らない。** 対象のボタン押下（Shift/Ctrl+左、中央、右）はフックでいったん握りつぶし、ワーカー側で SendMessageTimeout（SMTO_ABORTIFHUNG、50 ms）を使って判定する。該当しなければ、押下を SendInput で送り直す
- **押下を握りつぶしている間に来た、同じボタンの解放も握りつぶす。** 押下を送り直した後に、解放を送り直すこと（理由: 解放が押下より先に届くと、相手のアプリの状態が壊れる）。この順序は単体テストで保証すること
- タイトルバー上で左ボタンを押した場合（Shift・Ctrl なし）は握りつぶさない（理由: 普段のウィンドウ移動に遅延を入れない）

### 2.7 通知アイコン化（ウィンドウをタスクトレイにしまう）

- 対象ウィンドウを ShowWindow(SW_HIDE) で隠し、通知領域にそのウィンドウ用のアイコンを追加する。アイコンはウィンドウのアイコン（WM_GETICON、無ければクラスのアイコン）、ツールチップはウィンドウのタイトル
- そのアイコンを左クリック → ウィンドウを再表示してフォアグラウンドにし、アイコンを消す。右クリック → メニュー（元に戻す / 閉じる）
- **隠したウィンドウの一覧を `state/hidden_windows.json`（exe と同じフォルダ）に保存する**
  - アプリ終了時（正常終了）にはすべて再表示する
  - 起動時にファイルが残っていたら（前回異常終了した）、まだ存在するウィンドウをすべて再表示する
  - （理由: アプリが落ちたとき、ウィンドウが見えないまま取り残されるのを防ぐ）
- メインのトレイメニューに「隠したウィンドウをすべて戻す」を付ける
- 管理者権限のウィンドウなど、操作できないものは何もせずログに残す

### 2.8 ホイール

| 機能 | 実行内容 |
|---|---|
| カーソル下のウィンドウをスクロール | **実装しない。** Windows 11 の標準機能（非アクティブ ウィンドウをスクロール、ユーザーの環境では ON）に任せる（理由: かざぐるマウスはこれをホイールの横取りで実現しており、それがスクロール停止の原因と推測されるため） |
| スクロールバー上で高速スクロール | 標準の垂直スクロールバー（WM_NCHITTEST が HTVSCROLL、またはクラス名 "ScrollBar" の子ウィンドウ）の上でホイールを回したら、回転量を **N 倍**（設定 `fastScrollMultiplier`、既定 5）にして送り直す |
| カーソル位置に入力フォーカスを合わせる | ホイールを回したとき、カーソル下の部品がフォアグラウンドウィンドウの中にあれば、その部品に入力フォーカスを移す（UI Automation の SetFocus をワーカーで実行。200 ms でタイムアウト）。ホイールの入力そのものは遅らせず、素通しにする。背景のウィンドウは前面に出さない |

**スクロールバー判定の仕組み（重要）**：
- ホイールの入力を判定のために握りつぶして待つことは**しない**
- 代わりに、ワーカーがカーソル移動のたびに（最大 30 ms に 1 回）「今カーソルがスクロールバーの上にあるか」を判定してキャッシュする
- フックはホイールを受けたとき、キャッシュが新しく（100 ms 以内）、カーソル位置が同じで、スクロールバー上と判定されている場合**だけ**、握りつぶす。そしてワーカーに送り直しを頼む。それ以外はすべて素通し
- 送り直しが失敗したら（SendInput の戻り値が 0）、60 秒間はスクロールバーの横取りをやめ、ログに残す

### 2.9 その他

| 機能 | 実行内容 |
|---|---|
| 無効状態のウィンドウも移動できる | 左ボタンで押した位置が、無効状態（IsWindowEnabled が false。モーダルダイアログ表示中の親ウィンドウなど）のトップレベルウィンドウのタイトルバーなら、ドラッグで移動できるようにする。移動は SetWindowPos をワーカーで実行する。判定は §2.8 のスクロールバーと同じく、**ワーカーがカーソル移動のたびに判定してキャッシュし、フックはキャッシュを見るだけ**にする（理由: 左クリックは最も頻繁な操作なので、握りつぶして待つ方式にすると全クリックが遅れる）。WindowFromPoint は無効なウィンドウを返さないので、トップレベルウィンドウを Z 順にたどって探す。タイトルバーの範囲は GetTitleBarInfo の矩形を使う |
| プロセスの優先度 | アプリ起動時に ABOVE_NORMAL_PRIORITY_CLASS にする |
| トレイアイコン | 左クリック → 設定ファイルを開く。右クリック → メニュー。中央クリック → ジェスチャー機能の一時停止・再開。ダブルクリック → 何もしない。アプリをもう一度起動したとき → 設定ファイルを開く |
| タスクバーの並べ替えなど | 実装しない（Windows 11 の標準機能） |

一時停止の対象は、この指示書の機能（ジェスチャー、タイトルバー、ホイール、移動）だけです。つなぎ役には別の一時停止があります（指示書A）。

## 3. スクロール停止を起こさないための設計（必ず守る）

1. **マウスフック（WH_MOUSE_LL）は専用スレッド**に置く。スレッド優先度は THREAD_PRIORITY_HIGHEST、自前のメッセージループを回す
2. **フックの処理でしてよいこと**：入力イベントの記録、軽い状態判定、キューへの投入、キャッシュの参照、GetAsyncKeyState
3. **フックの処理でしてはいけないこと**：別プロセスへの SendMessage、UI Automation、ファイルやログの書き込み、ロックの長時間保持、描画、メモリ確保の多い処理
4. フックの処理時間を計測する。1 回あたり 5 ms を超えたらワーカー経由で警告をログに残す。終了時に平均と最大をログに残す
5. **フックの生存監視**：Raw Input（RIDEV_INPUTSINK）でマウスの入力を別ルートで受ける。Raw Input には入力が来ているのに、フックに 2 秒以上何も来ない場合は、フックが外されたとみなして付け直し、ログに残す（理由: Windows は応答の遅いフックを黙って外す）
6. 他のアプリに DLL を注入しない（SetWindowsHookEx はマウスの LL フックだけ使う）
7. フックで握りつぶした入力は、**必ず送り直すか、明確な理由（ジェスチャーとして消費した）で消費する**。「握りつぶしたまま宙に浮く」状態を作らない。押下を握りつぶしてから 2 秒たっても処理が決まらない場合は、送り直して通常状態に戻す（安全装置）
8. 自分の送った入力（dwExtraInfo = "LGAP"）は、どの機能でも処理せず素通しにする（理由: 無限ループと二重処理を防ぐ。つなぎ役の送る入力も含む）
9. **かざぐるマウスとの共存**：Kazaguru.exe が動いている間は、この指示書の機能をすべて止める。トレイの通知で「かざぐるマウスが動作中のため、ジェスチャー機能を停止しています」と 1 回知らせる。5 秒ごとに確認し、終了したら自動で再開する（理由: 両方が右ボタンを横取りすると誤動作する。ユーザーは移行期間に両方を起動しうる）

## 4. 構成

- 判定ロジック（ストローク判定、有効・無効、右ボタンの返し方、タイトルバー操作の握りつぶしと送り直しの順序、スクロールバー判定のキャッシュ、連続実行）は **LogiGap.Core に置き、Win32 に依存させない**。時刻・ヒットテスト・送信はインターフェースで受け取る
- フック、オーバーレイ、UI Automation、トレイアイコン化は LogiGap 側に置く
- 指示書A の `IFeatureModule`（またはそれに相当する仕組み）に「ジェスチャー」モジュールとして載せる

## 5. テスト（`dotnet test` で全部通ること。指示書A のテストも通り続けること）

1. ストローク判定：(0,0)→(12,0) で「→」。(0,0)→(0,12)→(12,12) で「↓→」。同じ向きの連続は 1 つ。9 px の移動ではストロークにならない
2. 有効・無効：「↓」は無効、「↓→」は有効、「↓→↑」は無効
3. 右クリックの返し方：
   - 動かさずに離す → 右の押下・解放がこの順に送り直される
   - 1000 ms 静止 → 右の押下が送り直され、以後は素通し
   - ストロークありで離す → 何も送り直されない。有効ならコマンドが 1 回だけ実行される
4. 連続実行：「←」入力中に左クリック 3 回 → 「戻る」が 3 回。離したときは実行されない
5. タイトルバー：中央クリックで押下を握りつぶし、判定が「タイトルバーでない」と返ったとき、押下 → 解放の順で送り直される（解放が先に来ていた場合も）。判定がタイムアウトした場合も送り直される
6. スクロールバー：キャッシュが古い（101 ms）とき、または位置が違うときは握りつぶさない。条件を満たすときは回転量 ×5 で送り直す
7. 安全装置：判定が 2 秒決まらないと送り直される
8. 自分の送った入力（"LGAP"）は、どの判定にもかからない
9. 隠したウィンドウ一覧の保存と復元（ファイルの読み書き部分）

## 7. 手動確認の手順（`app/README.md` に追記。ユーザー向けの日本語）

少なくとも次を含めてください。

1. **かざぐるマウスを終了してから**試すこと（共存時は自動で止まる、と明記）
2. ブラウザで ← → ↑↓ ↓→ ↓← を試し、それぞれ戻る・進む・更新・タブを閉じる・最小化になること
3. 右ドラッグで大きく円や文字を描き、軌跡が遅れずに付いてくること。有効な形の間は緑、それ以外は赤になること。離すと消え、何も実行されず、右クリックメニューも出ないこと
4. 2 つのモニターをまたいで描いても、線がつながること
5. 普通の右クリックでメニューが出ること。エクスプローラで、選択したファイルを右ドラッグしてコピーできること
6. タイトルバーの Shift+クリック、Ctrl+クリック、中央クリック、最小化ボタンの右クリックを試すこと。トレイにしまったウィンドウを戻せること
7. メモ帳など標準のスクロールバーの上でホイールを回すと、速くスクロールすること
8. 数日使って、スクロールが止まる現象が起きないか確かめること。起きたら、ログの「フックを付け直した」行を確かめること

## 8. やらないこと

- かざぐるマウスの設定画面の再現（設定はファイルで行う。設定画面は今後の課題）
- 設定に無いコマンド（音量調節、半透明化など）の実装
- 指示書A の機能の変更

## 9. 完了報告（日本語で）

1. 追加・変更したファイルの一覧と役割
2. `dotnet build` / `dotnet test` の結果
3. フックの処理時間（自分の環境で計測できた範囲で）
4. 指示書から外れた点と理由
5. 未確定事項（`// 要確認:` の一覧）
6. ユーザーが最初にすべき手動確認
