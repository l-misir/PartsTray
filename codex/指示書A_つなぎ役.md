## 1. 背景と目的

- ユーザーは Logitech の **MX Master 4**（マウス）を **Logi Bolt レシーバー**経由で使い、純正アプリ **Logi Options+** でポインタ速度とボタン割り当てを設定しています。
- マウスがつながり直すと（レシーバーの抜き差し、スリープ復帰、Easy-Switch など）、マウス側の設定は既定値に戻ります。Options+ が設定し直すまでの **15 秒〜1 分以上**、ポインタ速度が遅く、ボタンも割り当てどおりに動きません。
- 作るもの：**マウスがつながった直後から、Options+ が設定し直すまでの間だけ、同じ設定を肩代わりする常駐アプリ**。Options+ が設定を始めたら、**設定を戻さずに即座に手を引きます**。
- 一番避けたい事故は**二重実行**です。Options+ と自作アプリの両方が同じボタン押下を処理すると、Ctrl+C が 2 回、DPI の切り替えが 2 回（元に戻る）などが起きます。

## 2. 実機で確定している事実

調べたときの道具と生ログはリポジトリにあります。手本として必ず読んでください。

| 参照先 | 内容 |
|---|---|
| `logigap/hidpp.py` | HID++ の送受信の最小実装（Python）。C# 版の手本 |
| `logigap/decode.py` | 受信レポートの解読。各命令の引数・応答の並びの手本 |
| `data/devices.json` | MX Master 4 / MX Keys S の機能一覧（機能番号→インデックス）、現在の CID 一覧 |
| `logs/sniff_20261118_224803.log` | 抜き差し実験 1 回目（Options+ がリンク確立から約 2 秒で設定） |
| `logs/sniff_20261118_230321.log` | 常駐記録（Options+ がリンク確立から 15.6 秒後に設定開始。ボタン押下も含む） |
| `README.md` | ここまでの調査のまとめ |

ログの各行の末尾 `| 11 02 0d ...` が受信した生バイト列、`+  22.656s` がレシーバー検出からの経過時間です。ログ中の「Options+」「通知」「レシーバー」はツールが付けたラベルです。

### 2.1 機器と通信路

| 項目 | 値 |
|---|---|
| レシーバー | VID 0x046D / PID 0xC548（Logi Bolt） |
| HID++ の通信路 | レシーバーの HID コレクションのうち **UsagePage 0xFF00 / Usage 0x0001**（short レポート、ID 0x10、7 バイト）と **Usage 0x0002**（long レポート、ID 0x11、20 バイト）の 2 つ。**両方を開いて両方を読む**。short の送信は 0x0001 側へ、long の送信は 0x0002 側へ |
| 共有 | Windows はこのコレクションの入力レポートを、開いている**全員に同じものを配る**（実測で確認済み）。Options+ が受け取る応答は、自作アプリにも見える。CreateFile は FILE_SHARE_READ \| FILE_SHARE_WRITE で開くこと |
| MX Master 4 | wpid **0xB042**、現在のデバイス番号は **2**。番号は決め打ちせず、接続通知の wpid から求める |
| MX Keys S | wpid 0xB378、デバイス番号 3。**このアプリでは一切触らない** |
| ソフトウェアID（swid） | **Options+ は 0xE** を使う（実測）。**自作アプリは 0x5** を使う。0x0（通知用）と 0xE は絶対に使わない |

### 2.2 メッセージ形式

| 種類 | バイト列 |
|---|---|
| 接続通知（HID++1.0、short） | `10 dev 41 protocol flags wpid_lo wpid_hi`。flags の bit6（0x40）が 1 ならリンク切断、0 ならリンク確立。例：`10 02 41 10 02 42 b0` は MX Master 4 のリンク確立 |
| HID++2.0 要求・応答（long） | `11 dev featIdx (fn<<4 \| swid) params(16バイト)` |
| HID++2.0 通知 | 上と同じ形で swid = 0 |
| HID++2.0 エラー | `11 dev FF featIdx (fn<<4 \| swid) errCode ...` |
| HID++1.0 エラー | `10 dev 8F 元b2 元b3 errCode 00` |

### 2.3 MX Master 4 の機能（実行時に ROOT.getFeature で毎回求めること）

インデックスは参考値です。テストではこの値を使ってかまいません。

| 機能 | 機能番号 | 実測インデックス | 使う関数 |
|---|---|---|---|
| ROOT | 0x0000 | 0 | fn0 getFeature(idHi, idLo) → [index, type, ver]（index=0 なら無い）, fn1 ping |
| WIRELESS_DEVICE_STATUS | 0x1D4B | 4 | 通知 fn0：リンク確立直後に `status=01 request=01 reason=01`（再設定してほしい合図）が来る |
| REPROG_CONTROLS_V4 | 0x1B04 | 13 | fn2 getCidReporting(cidHi, cidLo) → [cidHi, cidLo, flags, remapHi, remapLo, flags2]。fn3 setCidReporting(cidHi, cidLo, flags, remapHi, remapLo)。flags の bit0 = 横取り(divert)、bit1 = bit0 を有効にする印。**横取り ON = 0x03、OFF = 0x02**。通知 fn0 divertedButtons：params に押下中の CID が最大 4 個（各 2 バイト、ビッグエンディアン）、全部 0 なら全部離した |
| ADJUSTABLE_DPI | 0x2201 | 20 | fn2 getSensorDpi(0) → [sensor, dpiHi, dpiLo, defHi, defLo]。fn3 setSensorDpi(0, dpiHi, dpiLo)。既定値 1000、範囲 200〜8000、50 刻み |
| THUMB_WHEEL | 0x2150 | 19 | fn0 getInfo → nativeRes=20, divertedRes=120, caps=0x03（実測）。fn1 getStatus → [reportingMode, invert, …]。fn2 setReporting(reportingMode, invert)。通知 fn0（横取り中のみ）→ [rotation(int16, BE), timestamp(uint16), rotationStatus, flags] |
| HIRES_WHEEL | 0x2121 | 18 | 触らない |
| SMART_SHIFT_ENHANCED | 0x2111 | 17 | 触らない（マウス本体に保存されていて、つながり直しても崩れない） |

サムホイールについて、まだ実測できていない点があります。
- 通知の並びは Solaar の実装に基づく推定です。実測できたのは触れたときの通知 `00 00 00 00 00 02` だけで、回転の実例はまだありません。回転量の取り出し方は、実機確認の項目（§10）に入れてください
- setReporting の引数 `(reportingMode, invert)` も Solaar に基づく推定です（Options+ の応答は空 `00 00` で、要求の中身は見えない）。書き込んだ後に getStatus で読み戻し、`01 01` になったか確かめてログに残してください

### 2.4 Options+ が設定し直すときの手順（実測、2 回とも同じ）

| リンク確立からの時間（1 回目 / 2 回目） | Options+ の動作 |
|---|---|
| +0.04 秒 / +15.59 秒 | 問い合わせを開始（機能の確認、バージョン取得など。読むだけ） |
| +0.88 秒 / +16.33 秒 | **setSensorDpi(1000)**：いったん既定値を書く |
| +1.02 秒 / +16.46 秒 | **setCidReporting(flags=0x22)** を 0x0052, 0x0053, 0x0056, 0x00C3, 0x00C4, 0x01A0 に順番に送る（横取りをいったん OFF） |
| 少し後 | 左右クリック（0x0050, 0x0051）に flags=0x00, flags2=0x03 を書く（分析用の通知。横取りはしない。無視してよい） |
| +1.65 秒 / +17.2 秒前後 | **setCidReporting(flags=0x23)** を同じ 6 個に送る（横取り ON） |
| +2.09 秒 / +17.55 秒 | **setSensorDpi(2200)**、続けて **THUMB_WHEEL setReporting**（その後の getStatus は `01 01` = 横取り・反転） |

- 2 回目の遅れは、Options+ がレシーバーのレジスタ 0xFC の準備完了を、間隔を倍々に延ばしながら待っていたため。マウス自体はリンク確立の直後から命令を受け付ける
- 応答はすべて swid=0xE で返ってくる。**Options+ が設定を始めた最初の合図は、swid=0xE の setSensorDpi / setCidReporting / THUMB_WHEEL setReporting のどれかの応答**

### 2.5 ユーザーの設定（再現する内容）

| 対象 | CID | Options+ での割り当て | 自作アプリでの再現方法 |
|---|---|---|---|
| ポインタ速度 | — | 2200 DPI | リンク確立直後に setSensorDpi(2200) |
| ホイールクリック（中ボタン） | 0x0052 | ポインタ速度の切り替え（2200 ⇔ 1100） | 横取りし、押すたびに DPI を交互に書く。つながり直すたびに 2200 から始める |
| 進む（親指側の前のボタン） | 0x0056 | Ctrl + C | 横取りし、押したら Ctrl+C を送る |
| 戻る（親指側の後ろのボタン） | 0x0053 | Ctrl + V | 横取りし、押したら Ctrl+V を送る |
| ジェスチャーボタン（親指部の上） | 0x00C3 | PrintScreen | 横取りし、押したら PrintScreen キーを送る |
| ハプティックパネル（親指の腹） | 0x01A0 | Win + ↑ | 横取りし、押したら Win+↑ を送る |
| SmartShift ボタン | 0x00C4 | ホイールモード切替（初期値） | **横取りしない**。マウス本体が自分で切り替える |
| サムホイール | — | 水平スクロール、速度 50%、方向反転 | 横取り（setReporting(1, 1)）し、回転を水平スクロールに変換して送る（§5.3） |

キーボード、ハプティクス、メインホイール、SmartShift の設定は対象外です。

## 4. 状態機械（中心部分。ここを最も丁寧に）

MX Master 4 との 1 回の接続（リンク確立からリンク切断まで）ごとに、次の状態を持ちます。

| 状態 | 意味 | トレイの表示 |
|---|---|---|
| `Disconnected` | レシーバーが無い、またはマウスが切断中 | 待機中 |
| `Active` | 肩代わり中（自分が設定し、ボタンを処理する） | 肩代わり中 |
| `Retreated` | Options+ に引き継いだ（何もしない） | Options+ に引き継ぎ済み |
| `Paused` | ユーザーが一時停止した | 一時停止中 |

### 4.1 遷移

1. **リンク確立**（接続通知で wpid=0xB042、flags の bit6 が 0）→ 新しいセッションを始めて `Active` へ
   - 機能インデックスを ROOT.getFeature で求める（キャッシュしてよいが、毎セッション 1 回は確かめる）
   - 続けて §4.2 の「適用」を行う。**リンク確立から 500 ms 以内に適用を始める**こと（理由: マウスが動き出した瞬間から設定が効いてほしい）
2. **Options+ の設定開始を検知**（`Active` 中に、MX Master 4 宛ての swid=0xE の応答で、ADJUSTABLE_DPI fn3 / REPROG_CONTROLS_V4 fn3 / THUMB_WHEEL fn2 のいずれか）→ **即座に `Retreated`**
   - 受信スレッド上で、その応答を処理したその場で状態を切り替える。以後に届くボタン・サムホイールの通知は処理しない（理由: Options+ は横取りを OFF→ON と書き直してから自分で処理を始める。最初の書き込みの時点で手を引けば、二重実行の窓はゼロになる）
   - 適用の途中なら、残りの書き込みは送らない
   - **横取りを OFF に戻す書き込みは送らない**（理由: Options+ が入れた設定まで消してしまう）
3. **`Retreated` の後片付け（1 回だけ）**：Retreated になってから 15 秒後に次を行う
   - 自分が横取り ON にした CID ごとに、Options+ が最後に書いた flags を記録しておく（Retreated 後に見えた swid=0xE の setCidReporting 応答から）
   - 15 秒後に getCidReporting で現在値を読む。Options+ がその CID に**一度も書かなかった**のに横取り ON のままなら、OFF（0x02）に戻す
   - サムホイールも同様に扱う。Options+ が setReporting を一度も書かなかったなら、setReporting(0, 0) で通常モードに戻す
   - Options+ が書いた CID には何もしない（理由: ボタンが「押しても何も起きない」状態を残さないため。Options+ が設定を見直してその CID を使わなくなった場合への保険）
4. **リンク切断**（接続通知の bit6 が 1）、またはレシーバーの取り外し → `Disconnected`。保留中の処理は捨てる
5. **ユーザーが一時停止** → `Paused`。何も送らず、通知も処理しない。解除したら、次のリンク確立までは `Retreated` と同じ扱い（理由: 解除した瞬間に Options+ と競合する書き込みをしない）

### 4.2 適用（`Active` に入ったとき、この順で）

1. setSensorDpi(0, 2200)
2. setCidReporting(cid, 0x03, remap=cid) を 0x0052, 0x0056, 0x0053, 0x00C3, 0x01A0 の順に
3. THUMB_WHEEL setReporting(1, 1)

- 各書き込みは応答（同じ featIdx・fn・swid=0x5）を待つ。タイムアウトは 1 秒、Busy（エラー 8）とタイムアウトは最大 3 回まで再送
- 各書き込みの前に、状態がまだ `Active` か確かめる
- 応答のタイムアウトが続いたら（マウスがすぐスリープしたなど）、ログに残して `Active` のまま待つ。次の通知や命令が届いたときに、未適用の分を再試行する

### 4.3 起動したときの判定（リンク確立の通知が来ない場合）

アプリ起動時に、MX Master 4 がすでにつながっていることがあります（ログオン直後の自動起動など）。

1. レシーバーを開き、デバイス番号 1〜6 に ping を送る。DEVICE_NAME（0x0005）が "MX Master 4"、または接続通知で wpid=0xB042 が確認できた番号を MX Master 4 とみなす
2. 0x0052 の getCidReporting を読む
   - 横取り ON で、かつ Options+ のプロセス（`logioptionsplus_agent.exe`）が動いている → `Retreated`（Options+ が設定済み）
   - それ以外 → `Active` にして適用する（理由: 横取り ON でも Options+ が動いていなければ、前回の自作アプリの残りなので、引き継いで処理する）

### 4.4 `Active` 中の処理

- **ボタン**：divertedButtons 通知を受けるたび、前回の押下中集合と比べる。**新たに現れた CID だけを「押した」として 1 回処理**する（離したときは何もしない）
  - 0x0052 → DPI を 2200 と 1100 で交互に切り替えて setSensorDpi
  - 0x0056 → Ctrl+C、0x0053 → Ctrl+V、0x00C3 → PrintScreen、0x01A0 → Win+↑
  - 実際の処理（SendInput、DPI の書き込み）は**受信スレッドとは別のワーカー**で行う。ただし「押した」の判定と状態の確認は受信スレッドで行い、Retreated 後に積まれた処理は捨てる
- **サムホイール**：回転の通知を §5.3 の式で水平スクロールに変換して送る
- **Options+ の通知以外の応答**（読むだけの問い合わせ）では状態を変えない（理由: 遅いケースでも、Options+ は問い合わせだけを早めに始めることがありうる）

## 5. 入力の送信

### 5.1 共通
- SendInput を使う。**すべての送信イベントの dwExtraInfo に 0x4C474150（"LGAP"）を入れる**（理由: 指示書B のマウスフックが、自作アプリ自身の送った入力を見分けるため）
- キーの組み合わせは「修飾キー押下 → キー押下 → キー解放 → 修飾キー解放」の順に、1 回の SendInput 呼び出しでまとめて送る
- ↑ キーには KEYEVENTF_EXTENDEDKEY を付ける。Win キーは VK_LWIN

### 5.2 PrintScreen
- VK_SNAPSHOT の押下・解放を送る（Windows の設定によっては Snipping Tool が開く。Options+ と同じ挙動なのでそれでよい）

### 5.3 サムホイール（速度 50%・反転の再現）
- 横取り中の分解能は 1 回転 120 単位、通常モードでは 1 回転 20 ノッチ（実測の nativeRes / divertedRes）
- Windows の 1 ノッチは 120。よって速度 100% なら、横取り中の 1 単位あたり `120 × 20 / 120 = 20`。**速度 s% なら 1 単位あたり `20 × s / 100`**（50% なら 10）
- 端数は捨てずに累積し、絶対値が 1 以上たまったら整数部分を MOUSEEVENTF_HWHEEL で送る
- 向きは設定 `thumbWheel.directionSign`（+1 / -1）で反転できるようにする。既定値は、Options+ 動作時と同じ向きになる値（`// 要確認:` を付けて、手動確認で決める）
- 速度と向きは設定ファイルで変えられるようにする

## 6. 安全のための約束

**書き込んでよい命令はこれだけです：**

| 命令 | 条件 |
|---|---|
| ADJUSTABLE_DPI fn3 setSensorDpi | `Active` 中のみ。対象は MX Master 4 だけ |
| REPROG_CONTROLS_V4 fn3 setCidReporting | `Active` 中の横取り ON（0x03）と、§4.1 の後片付けでの OFF（0x02）のみ。対象は §2.5 の 5 個の CID だけ |
| THUMB_WHEEL fn2 setReporting | `Active` 中の (1, 1) と、後片付けでの (0, 0) のみ |
| 読むだけの命令 | ROOT fn0/fn1、FEATURE_SET、DEVICE_NAME、getSensorDpi、getCidReporting、THUMB_WHEEL fn0/fn1 |

**禁止事項：**
- レシーバー（デバイス番号 0xFF）への書き込み、レジスタ操作、ペアリング操作
- MX Master 4 以外の機器への送信（ping を除く）
- swid 0x0 / 0xE の使用
- `Retreated` / `Paused` / `Disconnected` 中の書き込み（後片付けを除く）
- 例外でアプリが落ちること。受信スレッド・ワーカーの例外は捕まえてログに残し、続行する

## 7. 常駐まわり

- **多重起動しない**（名前付き Mutex）。2 つ目を起動したら、1 つ目にトレイのメニューを表示させて自分は終了する
- **トレイアイコン**：ツールチップに状態（§4 の表示）を出す。右クリックメニューの項目：
  - 状態の表示（クリック不可）
  - つなぎ役を一時停止 / 再開
  - 設定ファイルを開く（既定のエディタで `config.json`）
  - ログフォルダを開く
  - Windows 起動時に自動起動（チェック式。`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に登録・削除）
  - 終了
- **レシーバーの抜き差し**：1 秒ごとにレシーバーの有無を確認する（RegisterDeviceNotification を使ってもよい）。抜けたら `Disconnected`、差さったら開き直す
- **スリープからの復帰**でも同じように開き直す
- アイドル時の CPU 使用率はほぼ 0% にする（読み取りは重複 I/O かブロッキング読み取りで待ち、ポーリングで回さない）

## 9. テスト（`dotnet test` で全部通ること）

1. **解析**：§2.2 の各形式（接続通知、2.0 応答、2.0 通知、2.0 エラー、1.0 エラー）を正しく分類できる
2. **ログ再生テスト**：`logs/sniff_20261118_224803.log` と `logs/sniff_20261118_230321.log` の各行から、経過時間と末尾の生バイト列を読み取って状態機械に流す。送信は偽物で受け取る
   - 224803：リンク確立（+22.656 秒）で `Active` になり、適用の書き込みが §4.2 の順で出る。最初の Options+ の書き込み（+23.539 秒の setSensorDpi）で `Retreated` になる
   - 230321：リンク確立（+1.129 秒）で `Active` になり、+17.455 秒の Options+ の setSensorDpi で `Retreated` になる。その後のボタン押下（+24.168 秒の 0x0056、+25.743 秒の 0x0053）では**操作を 1 つも出さない**
   - 再生テストでは、偽の送信に対する自分の応答を偽装すること（ログに自分の応答は入っていない）
3. **合成テスト**：
   - `Active` 中にボタンを押したら、その操作がちょうど 1 回出る。押しっぱなしで通知が繰り返し来ても 1 回だけ。2 つ同時押しでもそれぞれ 1 回ずつ
   - 0x0052 を 3 回押すと、DPI の書き込みが 1100 → 2200 → 1100 の順に出る
   - Options+ の応答と同じ受信の直後に届いたボタン通知は、処理されない
   - 後片付け：Options+ が 0x0053 にだけ書かなかった場合、15 秒後に 0x0053 だけが OFF（0x02）に戻る。全部に書いた場合は何も書かない
   - 適用の途中で Options+ を検知したら、残りの書き込みは出ない
   - サムホイールの変換：速度 50% で 1 単位ずつ 12 回届くと、合計 120（1 ノッチ）になる。端数が累積される
4. ビルド警告は 0 を目指す。Nullable を有効にする
