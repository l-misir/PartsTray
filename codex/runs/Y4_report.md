高速スクロールを、**回転量に倍率を掛けて1回だけ送る方式**に戻しました。通常の縦バーでは `SendInput`、Chromium の画面端では内側の座標へ `WM_MOUSEWHEEL` を1回送ります。

「ウィンドウ・ホイール」に **「高速スクロールを使わないアプリ」** を追加しました。既定の `Acrobat.exe` と `AcroRd32.exe` では、高速スクロール・端の補助・届け直しをすべて休止し、元のホイールをそのまま通します。

Chromium の端では、窓と描画領域を裏で先読みします。端に移った直後や静止後で、その座標の判定がまだないときは、**最初の1ノッチを等倍で内側へ**届けます。新しく開いた窓でプロセス名や描画先の確認も間に合っていない場合は、除外指定を優先して通常の入力を通します。

指定コマンドで**ビルド成功（警告0・エラー0）、テストは全1,205件合格（失敗0・スキップ0）**でした。

### Claude が実機で確かめること

| アプリ | 確認する動き |
|---|---|
| VS Code | 最大化し、倍率50・端の補助オン・届け直しオフで試す。縦バー上の1ノッチで動きが長く残らず、画面右端へ移った直後と、そこで数秒止めた後のどちらも、最初の1ノッチで本文が動く。 |
| Acrobat／Reader | 既定の除外のまま、届け直しをオンにして本文・縦バー・画面端で回す。PDF が急に飛ばず、通常どおり動く。診断は `result=Excluded` で、ホイールの送信行は出ない。 |
| エクスプローラー | 最大化した長い一覧で、本文は通常速度、縦バーと画面右端は判定後に高速になる。`explorer.exe` を除外欄に追加して適用すると、同じ場所でも通常速度に戻る。 |
