`codex/指示書Y_画面の端でも効くようにする.md` の続きです。前回の直し（端の高速スクロール・ホイールの届け直し）は実機に入りましたが、**ユーザー（11/21）：「画面端スクロールは変わらなかったです」**（エクスプローラー・VS Code で試した）。記録では、入れ替えのあと「スクロールバー（Chromium の右端）を見分けました」は 1 回出たが、「スクロールバー（UI オートメーション）を見分けました」は 1 回も出ていない。

原因を実機で突き止めるため、**判定の様子を記録に出す仕組み**を足し、考えられる原因を先につぶしてください。

1. **診断の記録**：設定 `diagnostics.scrollProbe`（既定 false）。オンのとき、高速スクロールの判定（`Probe`）のたびに 1 行：カーソルの位置・モニターの端からの距離・端の補助を使ったか・内側の点・カーソルの下と内側の点の窓のクラス名（題名は書かない）・最大化か・昔ながら／Chromium の右端／UI オートメーションのどれで判定したか、またはどこで「違う」となったか（理由）・UI オートメーションにかかった時間・キャッシュを使ったか。1 秒に何十行も出ないよう、同じ位置・同じ結果が続くときはまとめる
2. **考えられる原因をつぶす**：
   - UI オートメーションの時間の上限（50ms）は、エクスプローラーなど遅いアプリでは足りない可能性が高い。判定は裏のスレッドなので、上限を 300ms にし、時間切れでも結果が出たら次からの判定のために覚えておく（その回は通常の速さ）
   - 端の補助で、内側の点の判定をしたのに、ホイールのときの「同じ位置の判定か」の確かめ（`Fresh` など）で、元の位置と食い違って捨てられていないか
   - エクスプローラー（`DirectUIHWND`）のスクロールバーが、UI オートメーションでどう見えるか（親へたどる途中で `ScrollPattern` に届くか、段数の上限 8 で足りるか）
   - VS Code（Chromium）で、画面の端の 1〜2 ドットが `Chrome_RenderWidgetHostHWND` の外（枠）にあり、内側の点でだけ当たる場合に、右端の帯の計算が内側の点ではなく元の位置で行われていないか
3. テストを足す（時間の上限・覚えておく・端の補助の位置の扱い）。今あるテストは全部通る
