## 修正 1（重要）：実ログの再生テストが、記録中のファイルを読んでいる

**原因**

- `LogiGap.Tests.csproj` は、テストの入力 `Fixtures/sniff_20261118_230321.log` を、`../../logs/sniff_20261118_230321.log` へのリンクで取り込んでいる
- このファイルを書いている記録用のツール（`tools/sniff.py --quiet`）は、11/18 23:03 から**今も動き続けていて、ファイルに追記している**。今朝の実機確認（11:26〜11:29 の抜き差しと、肩代わり中のボタン・サムホイール操作）も、このファイルに入った
- そのため、テストの入力が変わり、「全期間で入力ゼロ」の検証が失敗した。コードの不具合ではない
- 前回の修正は、テストの検証を今朝のデータの件数（207 件、合計 -370）に合わせた。しかし、ファイルは今後も伸び続けるので、次に誰かがマウスを使えばまた失敗する。**テストの入力は固定しなければならない**

**対応**

1. テストの入力を、`app/` の中に固定したコピーとして置く
   - `app/LogiGap.Tests/Fixtures/sniff_20261118_230321.log`：`logs/sniff_20261118_230321.log` の**先頭から、`===== 11:26:18 レシーバーが外されました =====` の行の直前まで**（1166 行になるはず）。行番号を決め打ちせず、この行を探して決める。見つからない、または 1166 行でない場合は、作業を止めて報告に書く
   - `app/LogiGap.Tests/Fixtures/sniff_20261118_224803.log`：`logs/sniff_20261118_224803.log` の全体（22:49 で記録が終わっている）
   - 文字コードは UTF-8（BOM なし）のまま。改行は元のファイルに合わせる。例：`[IO.File]::ReadLines(元, [Text.Encoding]::UTF8)` を `Select-Object -First 1166` し、`[IO.File]::WriteAllLines(先, 行, [Text.UTF8Encoding]::new($false))` で書く（改行は元の CRLF / LF を確かめて合わせること）
   - `logs/` のファイルは読むだけで、変更しない
2. `app/LogiGap.Tests/LogiGap.Tests.csproj` の 2 行を、`../../logs/...` へのリンクから、上のコピー（`Fixtures/...`）の取り込みに変える。`CopyToOutputDirectory="PreserveNewest"` は残す
3. `app/LogiGap.Tests/ReplayTests.cs` を直す
   - ループの中に足した「Active でない間は入力が増えない」の検証は、より強い検証なので**残してよい**
   - 最後の検証は、元の `Assert.Empty(h.Input.KeyEvents); Assert.Empty(h.Input.WheelEvents);` に戻す（両方のファイルとも）
   - 今朝のデータ用の分岐（`"Ctrl+V", "Win+Up"`、207 件、-370）と、その `// 要確認:` を消す
   - 理由：固定した範囲は、昨夜の記録と今朝 9:36 のスリープ復帰（Options+ が 0.58 秒で設定）までで、LogiGap が肩代わりしても実行すべき入力は無い。元のテストの意図（実ログを流しても、引き継ぎの判定が正しく、余計な入力を出さない）をそのまま確かめられる

## 修正 2（小）：サムホイールの記録が、回転していない通知でも出る

- Options+ がサムホイールを転送しているときは、指が触れただけの「回転 0」の通知も届く（実ログで確認した：`サムホイール回転 0` の行が多数ある）
- 今の `ObserveIgnoredInput` は、function 0 の通知なら回転 0 でも「サムホイール回転を検出」と記録してしまう。これでは、回していないのに「回転を検出」となり、確認を誤らせる
- 対応：既存の `ObserveInput` と同じく、`r.Parameters.Length >= 6` のときに先頭の int16 BE を回転量として読み、**0 でないときだけ**記録する（1 回だけの印も、そのときに立てる）
- テスト：回転 0 の通知を何件送っても記録されず、その後の 0 でない通知で 1 行だけ記録されること
