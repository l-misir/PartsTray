## 修正 1（重要）：起動時に MX Master 4 を特定できない

- 現状は ping だけを送り、同じレシーバーの接続通知で wpid を知った番号しか採用しない。しかし接続通知はリンクが変化したときにしか来ないので、**ログオン時の自動起動など、マウスがすでにつながっている状態でアプリを起動すると、次に抜き差しするまで何もしない**。ログオン直後は Options+ の起動も遅いので、肩代わりが最も必要な場面の一つ
- 指示書の §4.3 と §6 の矛盾は、次のように解決する（指示書の作者として確定する）
  - **ping に応答した番号には、機器を特定するための読むだけの照会を送ってよい。** 対象は ROOT.getFeature(0x0005) と DEVICE_NAME（0x0005）の fn0（名前の長さ）と fn1（名前の一部。引数は先頭からの位置）。名前が "MX Master 4" と一致した番号を wpid=0xB042 として扱う
  - それ以外の照会・書き込みを、MX Master 4 以外へ送ってはいけない点は変わらない
- テスト：起動時に、接続通知なしで dev2 が "MX Master 4" と名乗れば特定できること。dev3 が "MX Keys S" と名乗っても、そこへは名前照会以外を送らないこと

## 修正 2（重要・安全）：リンク確立のたびに、横取りの状態を確かめてから Active にする

- 現状はリンク確立で即 `Active` になる。しかし、マウスが設定を保ったまま再接続することがありうる（短い電波断、スリープからの復帰など）。そのとき Options+ は設定し直さないので、自作アプリは引き継ぎの合図を受け取れない。結果として、**Options+ と自作アプリの両方がボタンを処理する二重実行**になる
- 対応：リンク確立でも、起動時と同じ判定（`startupCheck` 相当）を必ず行う
  1. 機能を探したあと、getCidReporting(0x0052) を読む
  2. 横取りが OFF → マウスは設定を失っている → `Active` にして適用する（実測の 2 回はこちら）
  3. 横取りが ON で、Options+ のプロセスが動いている → Options+ の設定が残っている → `Retreated`（書き込みなし。後片付けも不要なので完了扱い）
  4. 横取りが ON で、Options+ が動いていない → 自分の設定の残りとみなして `Active`
  5. 例外：**同じアプリの実行中に、この機器の直前のセッションが `Active` のまま終わっていた**（Options+ に引き継がなかった）場合は、横取りが ON でも自分の残りとみなして `Active` にする（理由: Options+ が動いていても設定していないなら、誰もボタンを処理しなくなるため）
- Options+ のプロセスの有無は、判定の時点で調べる。Core は Win32 に依存させないので、`Func<bool>` などのインターフェースで受け取る
- この判定の読み取り 1 回ぶん、適用の開始が遅れる。リンク確立から 500 ms 以内という目標は、引き続きログで測れるようにする
- テスト：
  - 再生テスト 2 本は、0x0052 の照会に「横取り OFF」を返す偽の応答を足して、これまでどおりの時刻で `Active` → `Retreated` になること
  - リンク確立時に 0x0052 が ON で、Options+ が動いている → 書き込みが 1 つも出ず、ボタン通知を処理しないこと
  - 直前のセッションが `Active` のまま終わり、横取りが ON のままリンクが再確立 → `Active` になること

## 修正 3（中）：後片付けの対象を広げる

- 現状は「Options+ が一度も書かなかった CID」だけを OFF に戻す。しかし、自分の横取り ON の書き込みが Options+ の OFF より後に届く競合がありうる。その場合、**Options+ の最後の書き込みは OFF なのにマウスは ON のまま**になる（ユーザーが Options+ でそのボタンを初期設定に戻している場合に起こる）
- 対応：後片付けで OFF に戻す条件を、次のどちらかに広げる
  - Options+ がその CID に一度も書かなかった
  - Options+ の最後の書き込みで、bit0 が 0（横取り OFF）だった
- どちらの場合も、getCidReporting で現在 ON と確かめてから OFF を書く（Options+ の意図に合わせるだけなので安全）。送信検査（ValidateCommand）の後片付けの条件も合わせて直す
- テスト：Options+ が 0x0053 に 0x22 だけを書き、0x23 を書かなかった。マウスは ON のまま → 後片付けで 0x0053 が OFF になる
