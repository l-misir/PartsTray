`codex/指示書Y_画面の端でも効くようにする.md` の続き（4 回目）です。前回（Y3）の直しを実機で試したユーザーの言葉（11/21）：

- 「VS Code でスクロールやってみましたが、1 回のスクロールにかかる時間が長すぎ＆その割にスムーズにスクロールしてるようには見えないので結構微妙ですね…（バーの上）」→ Y3 で高速スクロールを「元の大きさのホイールを倍率の回数」に分けたため、VS Code が 1 回ずつなめらかに動かそうとして遅くなった。**Y3 より前の「倍率を掛けた 1 回」では、VS Code のバーの上でちゃんと効いていた**
- 「端にすると必ず 1 回目のスクロールは反応しなくて、1 回スクロールを止めると反応しますね」→ 判定が裏のスレッドで終わるまで、1 回目はそのまま端の列（何もない所）に届いている
- 「Acrobat に関しては瞬間移動するのでない方がマシです。反応しないやつは何もない場合の動作になったほうがいい（自動でできないなら選択アプリによる除外とか？）」

直すこと：
1. **送り方を戻す**：高速スクロールは、Y3 より前と同じく**倍率を掛けた 1 回**で送る（SendInput）。Chromium の端の届け直し（PostMessage）も、倍率を掛けた 1 回の `WM_MOUSEWHEEL` にする。分けて送る仕組みは消す
2. **アプリを選んで高速スクロールから外す**：設定 `wheel.fastScrollExcludedProcesses`（プロセス名の一覧、既定 `["Acrobat.exe", "AcroRd32.exe"]`）。そのアプリの窓では、高速スクロール・端の補助・端の届け直しを**何もしない**（ふつうのホイールをそのまま通す）。設定画面の「ウィンドウ・ホイール」に、今のジェスチャーの除外アプリの欄と同じ作りの欄を足す（説明：「高速スクロールがうまく動かないアプリを足すと、そのアプリではふつうのスクロールになります」）。プロセス名の見分けは、今のジェスチャーの除外と同じ仕組みを使う（裏で調べて覚えておく）
3. **Chromium の端の 1 回目**：Chromium の作りの窓（`Chrome_RenderWidgetHostHWND`）の端の判定は、`WindowFromPoint`・クラス名・クライアント領域だけで決まり軽いので、**裏の判定を待たずにその場で決める**（フックの中でやるなら数マイクロ秒で終わることを確かめる。重い場合はフックの外の今の仕組みのまま、1 回目だけは内側の点への届け直し（倍率なし）をする）。どちらにしても 1 回目から内側に届くようにする
4. テスト：1 回で送る（分けない）、除外アプリでは何もしない、既定の除外、Chromium の端の 1 回目
