## 1. スマホ・タブレットの絵（`app/PartsTray/DevicePictures.cs`）

ユーザーが見本から選んだ形（11/21）：「P4 の大きさで、P2 みたいに中を抜いて（ホームボタンはなし）」「T1 の大きさで、スマホみたいに中を抜いて」。

- 本体の形と大きさは、今の仮の絵（`Phone`：幅 `a.Width * 0.52f`・高さいっぱい・角の半径 `w * 0.22f`、`Tablet`：高さ `a.Height * 0.72f`・幅いっぱい・角の半径 `h * 0.14f`）のまま変えない
- **中を抜く**：4 倍で描いて縮め、0/1 に分けた**後の 1 倍の画像**で、本体の外枠 1 ドットを残して内側を全部透明にする。キーボードやゲームパッドの穴（縮小後に抜く）と同じ作りにする
  - 本体の上端 `t`・下端 `b` は、真ん中の列で不透明な点の最初と最後。左端 `l`・右端 `r` は、`(t + b) / 2` の行で不透明な点の最初と最後
  - `l < x < r` かつ `t < y < b` の点を透明にする（枠の太さは上下左右とも 1 ドット）
- 16・20・24・32 ドットのどれでも、枠が途切れず、内側に穴が残ること
- 「仮の絵」というコメントは、決まった形の説明（ユーザーの言葉と日付）に書き換える

（参考：見本を描いた式。4 倍で描く箱 `a` の作り方は今の `DevicePictures` と同じ）

```csharp
// 1 倍の画像 pic（0/1 に分けた後）で
int t = -1, b = -1, l = -1, r = -1, mid = size / 2;
for (int y = 0; y < size; y++) if (pic.GetPixel(mid, y).A > 0) { if (t < 0) t = y; b = y; }
for (int x = 0; x < size; x++) if (pic.GetPixel(x, (t + b) / 2).A > 0) { if (l < 0) l = x; r = x; }
for (int y = t + 1; y <= b - 1; y++) for (int x = l + 1; x <= r - 1; x++) pic.SetPixel(x, y, Color.Transparent);
```

## 2. 最大化しているウィンドウの切り替えを、ホイールで前後に選べるようにする

### 2.1 ユーザーの使い方（なぜこう作るか）

- ユーザーは MX Master 4 の「ホイールモードの切り替え」ボタン（ホイールの後ろ、人差し指）を使っていないので、Options+ でそこに「切り替え」のキー（`windowKeys.nextMaximized`）を割り当てる
- 押すと、今と同じく次の最大化ウィンドウへ移る。**押してから少しの間だけ、ホイールを回して前後に選べる**ようにする。ユーザーの言葉：「何かしらのボタン＋縦か横のスクロールを想定」「多分横ホイールなら楽かな」（人差し指でボタン、親指でサムホイール）
- 右ボタン＋ホイールは断られた（「右クリックは中指なので、薬指＋中指になって疲れる」）
- PartsTray の方針は「ふだんはホイールを横取りしない」。横取りするのは、切り替えのキーを押した直後の短い間だけにする

### 2.2 動き

1. 切り替えのキー（`nextMaximized`）が押されたら、今までどおり次へ移り、**選ぶ時間**を始める（`wheelSwitchMs` ミリ秒。0 なら始めない）
2. 選ぶ時間の間は、縦のホイール（`WM_MOUSEWHEEL`）と横のホイール（`WM_MOUSEHWHEEL`）を**取り込んで（アプリには渡さず）**、前後の切り替えにする
   - 縦：下に回す（delta が負）＝次、上（正）＝前
   - 横：右（delta が正）＝次、左（負）＝前。`reverseHorizontal` が true なら逆（ユーザーは Options+ でサムホイールの向きを反転しているので、どちらが右になるか実機で決める）
   - 縦と横それぞれで delta を足していき、`wheelSwitchStep`（既定 120）たまるごとに 1 つ進む・戻る。向きが変わったら、たまった分を 0 に戻す
   - ホイールを受け取るたびに、選ぶ時間を `wheelSwitchMs` から数え直す（回している間は終わらない）
3. 選ぶ時間は、時間切れか、マウスのボタン（左・右・中・戻る・進む）が押されたら終わる。押されたボタンは**そのまま通す**
4. PartsTray 自身が送った入力（`MSLLHOOKSTRUCT.dwExtraInfo == KeyStroke.ExtraInfo`）は数えない・取り込まない。Options+ が送った横スクロール（injected）は数える（Options+ はサムホイールを injected の横スクロールとして送ることが多い）
5. 選ぶ時間が終わったら、その間に受け取ったホイールを記録に 1 行書く（例：「ホイールで切り替え：縦 3 回（合計 -360）、横 5 回（合計 75）、次へ 2・前へ 0」）。**実機で `wheelSwitchStep` と向きを決めるため**。機器の名前やウィンドウの名前は書かない

### 2.3 前へ（新しく足す）

- `WindowKeysModule` に「前へ」を足す：今の候補の並び（重なりの上から）で、**一番下のもの**を前面にする（今のウィンドウはそのまま。次へ＝今のを一番下へ、の逆回しになり、次へ・前へで行ったり来たりできる）
- 前面のウィンドウが候補にないときは、一番下のもの
- キーでも使えるように `windowKeys.previousMaximized`（既定は空＝使わない）を足す。押したときも選ぶ時間を始める

### 2.4 フックの作り

- **選ぶ時間の間だけ**、`WindowKeysModule` が自分で `WH_MOUSE_LL` を入れ、終わったら外す（ジェスチャーの設定が切れていても動くように。`GestureModule` のフックには手を入れない）
  - フックを入れるのは UI のスレッド（`WM_HOTKEY` を受ける窓と同じスレッド）
  - フックの中では重いことをしない。切り替えは自分の窓に `PostMessage` して、フックの外でする
  - 時間切れは `System.Windows.Forms.Timer` などで UI のスレッドで扱う
  - 例外が出たら入力を素通しにして、フックを外す
- 前後の計算（delta をためる、向き、時間の延長・終わり）は **`PartsTray.Core` の純粋なクラス**にして、時計を渡せるようにしてテストする（例：`WindowSwitchWheel`。OS に触れない）

### 2.5 前面にできないとき

ホイールで 2 つ目以降に移るとき、PartsTray は前面のプロセスではないので、`SetForegroundWindow` が断られて、タスクバーが点滅するだけになることがある（Windows の決まり）。

- `SetForegroundWindow` のあと前面が変わっていなければ、**中身が空のマウス入力**（`INPUT_MOUSE`、移動量 0、`dwExtraInfo = KeyStroke.ExtraInfo`）を `SendInput` で 1 つ送ってから、もう一度 `SetForegroundWindow` する（PowerToys と同じ手）
- それでも変わらなければ、記録に 1 行書いて諦める（同じ選ぶ時間の中では 1 回だけ）
- Alt キーを押す手は使わない（離したときにアプリのメニューが開くことがあるため）

### 2.6 設定（`PartsTray.Core/Settings.cs` の `WindowKeySettings`）

| 項目 | 既定 | 範囲 | 意味 |
|---|---|---|---|
| `previousMaximized` | `""` | キーの書き方（HotkeyText） | 前へのキー。空なら使わない |
| `wheelSwitchMs` | `1500` | 0〜5000 | 選ぶ時間。0 でホイールでは選ばない |
| `wheelSwitchStep` | `120` | 1〜1200 | 1 つ進むのに要る delta |
| `reverseHorizontal` | `false` | | 横のホイールの向きを逆にする |

- 3 つのキー（`maximize`・`nextMaximized`・`previousMaximized`）は、空でないもの同士が同じならエラー（今の 2 つの決まりを 3 つに広げる）
- 設定画面（`app/PartsTray/SettingsWindow.Keys.cs`）に、前へのキーの欄・選ぶ時間（ミリ秒）・横の向きを逆にする、を足す。説明文は短く、ユーザーの使い方が分かるように（例：「切り替えのキーを押してから、この時間のあいだはホイールで前後を選べます。回している間は延びます」）
- 肩代わり中のボタンの選択肢（`ButtonSettings.Action`）にも `PreviousMaximized`（「最大化しているアプリを前へ」）を足す（`Maximize`・`NextMaximized` と同じく、決めたキーを送る）
