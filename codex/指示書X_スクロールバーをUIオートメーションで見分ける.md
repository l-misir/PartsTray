## 1. ユーザーの言葉と、今の動き

- 11/21：「スクロールバーでの高速スクロールができないですね」。設定（`wheel.fastScrollOnScrollBar = true`、倍率 50）はオン
- 今の見分け方（`PartsTray.Core/PointerWindowPolicy.cs` の `IsVerticalScrollBar`）は、Windows の昔ながらのスクロールバー（クラス名 `ScrollBar`、または `WS_VSCROLL` の窓の非クライアント領域 `HTVSCROLL`）だけ。Chrome・Edge・Claude（Electron）・VS Code・Discord などは自分でスクロールバーを描くので、見分けられない
- ユーザーの決定：「UI オートメーションで直してみて。駄目だったら位置でやりましょう」

## 2. やること

1. **見分け方を足す**（今の見分けはそのまま残し、だめなときに次を試す）：UI オートメーションで、カーソルの下の要素から親へたどり、**縦にスクロールできる要素**（`ScrollPattern` があり `VerticallyScrollable` が true）を探す。見つかったら、その要素の範囲（`BoundingRectangle`）の**右端から、スクロールバーの太さ（`GetSystemMetricsForDpi(SM_CXVSCROLL)`、その画面の DPI で）＋ 2 ドット**までの帯にカーソルがあれば「スクロールバーの上」
   - たどるのは親へ数段まで（例 8 段）。窓の一番上（ルート）を越えない
   - 横書き・右から左の言語は考えなくてよい
2. **速さ**：UI オートメーションは遅いので、今の `Probe`（判定用のスレッドで調べて、位置ごとに覚えておく）の中で調べる。フックの中では呼ばない。1 回の調べに時間の上限（例 50ms）を付け、超えたら「スクロールバーではない」として次に進む
3. **重さ**：同じ窓・同じ要素なら、範囲を覚えておいて（例 2 秒）、UI オートメーションを毎回呼ばない
4. **記録**：初めて UI オートメーションで見分けられたら 1 回だけ記録（「スクロールバー（UI オートメーション）を見分けました」）。アプリの名前・窓の題名は書かない
5. 見分ける純粋な部分（範囲と帯の計算、たどり方の決まり、覚えておく決まり）は `PartsTray.Core` に置いてテストする

## 3. テスト

- 今あるテストは全部通る
