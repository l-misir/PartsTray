# 指示書L：オウム・CPU 使用率・温度・メモリを別々のアイコンにして、数字を大きくする

## 0. この指示書の目的

### 0.1 ユーザーの要望（11/20）

今の CPU まわりのアイコンは 2 つで、数字が小さい。

| 今 | 中身 |
|---|---|
| オウム（NotifyIcon の番号 2） | 上にオウム（高さ 10 ドットに縮む）、下に CPU 使用率の数字（白） |
| 温度・メモリ（番号 1、LogiGap の本体のアイコン） | 上に CPU 温度（赤）、下にメモリ使用率（白） |

見本を 4 案作って見せたところ、ユーザーは **B 案** を選んだ。

| B 案 | 中身 | 数字の色 |
|---|---|---|
| オウム | アイコンいっぱいの大きさのオウムだけ（数字なし） | － |
| CPU 使用率 | 大きな数字 1 つ | 水色 `#64D2FF` |
| 温度 | 大きな数字 1 つ | 赤 `#FF3B30`（今の tempColor） |
| メモリ | 大きな数字 1 つ | 白 `#FFFFFF`（今の memoryColor） |

並びの希望は、左から オウム・CPU 使用率・温度・メモリ・マウス・キーボード・ヘッドホン（並びは Windows の設定でユーザーが決める。アプリからは変えられない。`TrayOrder.cs` の説明を参照）。

### 0.2 見本で決めた数字の大きさ（アイコン 20px、拡大率 125%）

- 数字の形は今の `DigitArt` の "thin"（Tahoma をにじませずに描く。横は文字のある所、縦は「0」の上下で切る）と同じ作りで、文字を大きくする
- 「88」が幅 20・高さ 20 に収まる一番大きな文字（0.25px 刻みで探した）は **20.5px**。このとき「88」は **幅 20・高さ 15**（今は 13.3px で幅 13・高さ 9）
- 1 桁は 2 桁と同じ文字の大きさで、真ん中に置く（11/19 のユーザーの指定：「1 桁の時は横いっぱいまで広げなくていい。2 桁の時と同じ大きさで真ん中に表示」）
- 数字はアイコンの真ん中（横も縦も）に置く。20px なら上下に 2〜3 ドットの余白

### 0.3 方針

- 既存のアイコンの番号（Windows はアイコンを「アプリ＋番号」で覚え、ユーザーが設定で表示にした状態と並びを番号ごとに記憶する）を変えない：本体 1、オウム 2、電池 11〜16。新しい 2 つは **CPU 使用率 9、メモリ 10** にする（§3）
- 今の 2 段の描き方は、設定で戻せるように残す（§2）
- 電池のアイコンの描き方は変えない

**作業の順番**：本体のコード（§2〜§5）を先に書き、ビルドが通ってからテスト（§6）と README（§7）を書く。

## 2. 設定（Settings.cs）

### 2.1 CPU 使用率のアイコン（新規）

`MonitorSettings` に `Cpu` を足す。

```csharp
public sealed record CpuSettings
{
    public bool Enabled { get; init; } = true;          // CPU 使用率を別のアイコンで出す
    public string Color { get; init; } = "#64D2FF";     // 数字の色（水色。11/20 ユーザー：本当は CPU 使用率は水色にしたかった）
}
```

`Validate`：`Cpu` が null でない。`Cpu.Color` が `#RRGGBB`。

### 2.2 オウムの数字

`ParrotSettings.CpuText` の既定を `"bottom"` から **`"none"`** に変える（数字は CPU 使用率のアイコンへ移るので、オウムはアイコンいっぱいに描く）。`"top"` / `"bottom"` は今までどおり使える（オウムにも数字を出したい人向け）。

### 2.3 温度とメモリを分けるか

`TempMemorySettings` に `Split` を足す。

```csharp
public bool Split { get; init; } = true;   // true = 温度（本体のアイコン）とメモリ（別のアイコン）に分けて大きな数字。false = 今までの 2 段
```

### 2.4 そのほか

- ユーザーの設定ファイルは `"monitor": { "digitStyle": "thin" }` だけなので、上の既定値がそのまま効く
- 既存の項目は消さない・意味を変えない

## 3. アイコンの番号（TrayIds）

### 3.1 今の割り振り

WinForms の `NotifyIcon` は、作った順に 1, 2, 3… と番号（Windows の uID）を振る（`NotifyIcon` の中の通し番号）。今は次のとおり。

| 番号 | 作る所 | アイコン |
|---|---|---|
| 1 | `TrayContext`（Program.cs） | 本体（温度・メモリ、状態の説明、左クリック・中クリック・バルーン通知） |
| 2 | `MonitorModule` のコンストラクタ | オウム |
| 3〜10 | `BatteryModule` のコンストラクタで作って捨てる（表示しないので Windows に登録されない） | なし。前の版の電池アイコンが番号 3・4 で覚えられているので避けた |
| 11〜16 | `BatteryModule` の枠（`IconSlot` 6 つ） | 電池（マウス・キーボード・ヘッドホン…） |

### 3.2 新しい割り振り

| 番号 | アイコン |
|---|---|
| 1 | 本体（温度。`Split = false` なら今までの 2 段） |
| 2 | オウム |
| 3〜8 | 作って捨てる（使わない） |
| **9** | **CPU 使用率（新規）** |
| **10** | **メモリ（新規）** |
| 11〜16 | 電池（変えない） |

- `MonitorModule` のコンストラクタで、オウム（2）の直後に、使わない NotifyIcon を 6 つ作って捨て（3〜8）、続けて CPU 使用率（9）、メモリ（10）を作る
- `BatteryModule` の「8 つ作って捨てる」行は消す（電池の枠は今までどおり 11 から）。説明のコメントは、番号の表がある所（`TrayIds`）を指すように直す
- 番号の表は `TrayIds`（新規）に定数とコメントでまとめる。`MonitorModule` と `BatteryModule` はその定数を参照する
- **確かめ**：作った `NotifyIcon` の番号を、リフレクションで `NotifyIcon` の非公開のインスタンスの欄（.NET 9 の WinForms では `_id` のはず）から読み、期待した番号と違えばログに 1 行書く（`要確認` を含める）。欄が見つからない・読めないときは何もしない（例外を外に出さない）。動きは変えない（番号がずれても止めない）
- `GapModule` と `GestureModule` のコンストラクタの中で `NotifyIcon` を作っていないことを確かめ、報告に書く（`HiddenWindowManager` はウィンドウを隠したときに作るはず。起動時に作る経路があれば報告する）

## 4. 大きな数字（DigitArt と Core）

### 4.1 文字の大きさの選び方（Core の純粋な関数）

`LogiGap.Core` に、測り方を受け取って文字の大きさを選ぶ関数を足す（GDI+ を使わずにテストできるように）。例：

```csharp
// measure(px, text) は、その大きさで描いた text の点の幅と高さを返す。
public static float LargestFit(Func<float, (int Width, int Height)> measure, int size, float min, float max, float step)
```

- `max` から `step` ずつ下げ、`measure` の幅と高さがどちらも `size` 以下になった最初の大きさを返す。`min` まで下げても収まらなければ `min` を返す
- 名前と置き場所（`MonitorMath` か新しい静的クラス）は任せる

### 4.2 DigitArt に足すもの

- `Big(int? value, int size, string style)`（名前は任せる）：大きな数字の点（`bool[,]`）を返す。`value` が null なら `--`
- **thin**：
  - 基準の大きさ `basePx` ＝「88」が幅 `size`・高さ `size` に収まる一番大きな文字（§4.1 で、`min = size * 2/3`、`max = size * 1.5`、`step = 0.25`）。大きさごとにキャッシュする
  - 1 桁・2 桁・`--` は `basePx` で描く（同じ高さ。真ん中に置くのは描く側）
  - 3 桁（100 以上）は、`basePx` で幅に収まればそのまま。収まらなければ、`size * 2/3`〜`basePx` の範囲で幅に収まる一番大きな文字で描く。それでも収まらなければ `basePx` の「99」（ツールチップは正しい値）
  - 縦の切り方は今の `Thin` と同じ（その大きさの「0」の上下）
- **wide**（点の文字を伸ばす形。ユーザーは使っていないが壊さない）：`MonitorFont.SelectHeight(size, size)`（20px なら 9）の高さで、`MonitorFont.Digits(text, height, size, "wide")`。3 桁は `MonitorFont.FitNumber` に合わせる
- 今の `Fit` / `Mask` / `Height` は消さない（2 段の描き方とオウムの数字で使う）

### 4.3 見本の値（実装の確かめ用）

20px・thin で `basePx = 20.5`、「88」の点は幅 20・高さ 15 になるはず（見本のプログラムで確かめた値。Tahoma は Windows の標準のフォント）。ずれたら、ずれた値を報告に書く。

## 5. MonitorModule

### 5.1 アイコン

| アイコン | 表示する条件 | 描くもの | ツールチップ |
|---|---|---|---|
| オウム（2） | 今と同じ（`monitor.enabled` かつ `parrot.enabled`） | 今と同じ（`cpuText` の既定が none になるので、絵はアイコンいっぱい） | 今と同じ（`CPU 32%`） |
| CPU 使用率（9） | `monitor.enabled` かつ `cpu.enabled` | 大きな数字（`MonitorMath.Round(cpu)`、色 `cpu.color`） | `CPU 32%` |
| 温度（本体 1） | 今と同じ（`TempEnabled`） | `split` なら大きな数字（温度の平均、色 `tempColor`）。`split = false` なら今の 2 段 | 今と同じ（状態の文＋温度＋メモリの行） |
| メモリ（10） | `TempEnabled` かつ `split` | 大きな数字（メモリ使用率、色 `memoryColor`） | `メモリ 49%（7.8/16.0 GB）`（今の本体のツールチップのメモリの行と同じ書き方） |

- 数字は横も縦も真ん中に置く（`(size - 幅) / 2`、`(size - 高さ) / 2`）
- 温度が取れないときは `--`、メモリが取れないときは `--`（今と同じ扱い）
- 新しい 2 つの右クリックは、オウムと同じく `TrayContext` のメニュー（`ContextMenuStrip = menu`）。左クリック・中クリックは何もしない
- 表示・非表示は、オウムと同じく `TrayOrder.Want` を使う。`order.Register` も呼ぶ（rank：オウム 0、CPU 1、温度 2、メモリ 3。今は記録のためだけ）
- 本体（番号 1）の `Visible` は今までどおり `TrayContext` が持つ（変えない）

### 5.2 描き替え

- 取得の周期（`sampleIntervalMs`、既定 200ms）ごとに描く。ただし **CPU 使用率とメモリのアイコンは、文字・色・大きさが前と同じなら描き替えない**（アイコンの差し替えを減らす。`IconSlot.Replace` を毎回呼ばない）。温度も同じでよい
- 通知領域で並べ替え中（`TrayInteraction.Busy`）は、どのアイコンも描き替えない・ツールチップも変えない（今の作りと同じ考え方）
- `NotifyIcon.Text` は 127 文字まで（今の切り詰めと同じ）

### 5.3 後片付け

- `Dispose` で、新しい 2 つも非表示にしてから破棄し、アイコンのハンドルを解放する（今のオウムと同じ）
- 設定で無効にしたら非表示にして、アイコンのハンドルを解放する（今のオウムと同じ）

`app/README.md` の「オウムと温度・メモリのアイコン（指示書 J）」の節を直す。

- アイコンが 4 つ（オウム・CPU 使用率・温度・メモリ）になったこと、それぞれの中身と色

- 電池のアイコンの描き方、つなぎ役（`GapSession`・`GapModule`）、ジェスチャーの動きを変えない
