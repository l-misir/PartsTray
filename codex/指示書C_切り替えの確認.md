# 指示書C：切り替えを確かめるためのログと通知

## 0. この指示書の目的

指示書A のつなぎ役（`GapSession`）は、マウスの再接続から Options+ が設定を始めるまでの間だけ、ボタンとサムホイールを肩代わりする。実機では、肩代わりが接続から 0.2 秒以内に始まり、13〜15 秒後に Options+ へ引き継がれることを確認できた。

ユーザーが確かめたいのは、**切り替えの前後で二重動作が起きていないこと**である。今の作りでは、次の 2 点が確かめにくい。

1. **引き継ぎの後に押したボタンが、ログに残らない。** `GapSession.Receive` は、状態が Active のときだけ `ObserveInput` を呼ぶ。そのため、引き継ぎ後のボタン押下は何も記録されない。「LogiGap は何もしなかった」ことと「ボタンが押されなかった」ことを、ログで区別できない
2. **切り替わった瞬間が、その場で分からない。** ユーザーはログをリアルタイムで見ていない。切り替えの直後にボタンを試したくても、いつ切り替わったか分からない

そこで、次の 2 つを追加する。

- **確認用のログ**：LogiGap が実行しなかったボタン押下とサムホイールの回転を、理由つきで残す
- **切り替えの通知**：肩代わりの開始と、Options+ への引き継ぎのときに、Windows の通知を出す（設定で切れる）

**動作そのもの（何を送り、何を送らないか）は一切変えない。** 追加するのは観察と表示だけである。

## 2. 確認用のログ（GapSession）

### 2.1 実行しなかったボタン押下を記録する

**何をするか**

- 現在のデバイスから届いた REPROG_CONTROLS_V4（0x1B04）の divertedButtons 通知（function 0）を、**状態が Active でないときも観察する**。ただし一時停止中（`paused`）は、今までどおり何も観察しない
- その通知で**新たに押された** CID のうち、`sessionSettings.Buttons` に設定のあるものについて、1 回の押下につき 1 行のログを書く
- 書式（例）：

  ```
  ボタン CID=0053 押下: LogiGap は実行しない（Options+ に引き継ぎ済み） 設定=Keys Ctrl+V
  ```

  - 理由の文言は状態で分ける
    - `startupCheck` が true の間：「接続判定中」
    - それ以外：「Options+ に引き継ぎ済み」
  - 「設定=」の後には、今の実行ログ（`ボタン CID=... 操作=...`）と同じ形で、action と keys を書く
- Active のときの処理（`ObserveInput`、`pressed`、`actions`）は**変えない**

**押下の判定に使う集合**

- 押下の判定用に、新しい集合（例：`heldButtons`）を持つ。この集合は、現在のデバイスから divertedButtons 通知が届くたびに、**状態にかかわらず**その通知の CID の集合で置き換える（Active のときも更新する）
- 「新たに押された」とは、この通知に含まれ、直前の `heldButtons` に含まれない CID のことをいう
- `heldButtons` を空にするのは、リンクのセッションが始まるとき（`Begin`）と、終わるとき（リンク切断、`ReceiverLost`、`SetPaused`）だけにする。**`Invalidate` では空にしない**
- 理由：肩代わり中にボタンを押したまま Options+ に引き継がれると、引き継ぎ後の最初の通知にもその CID が入っている。`Invalidate` で空にすると、これを「引き継ぎ後の新しい押下」と誤って記録してしまう。実際には LogiGap が押下の時点で実行済みなので、二重動作の確認を誤らせる

**理由（なぜ観察だけで済むか）**

- divertedButtons 通知は、HID の入力レポートなので、レシーバーを開いているすべてのプロセス（LogiGap と Options+）に届く。引き継ぎ後は Options+ が転送を有効にしているので、LogiGap にも同じ通知が届き続ける。これを記録するだけで、「押されたが LogiGap は実行しなかった」ことをログで示せる
- 記録は観察だけで、`actions` に積まない。送信もしない。これにより、動作が変わる余地をなくす

### 2.2 サムホイールの回転を記録する

- 状態が Active でないときに、THUMB_WHEEL（0x2150）の通知（function 0）が届いたら、**1 回のリンクのセッションにつき 1 回だけ**、次の形のログを書く

  ```
  サムホイール回転を検出: LogiGap は送信しない（Options+ に引き継ぎ済み）※このリンクでは 1 回だけ記録
  ```

  - 理由の文言は 2.1 と同じ規則で分ける
- 「1 回だけ」の記録済みの印は、`Begin` で戻す
- 理由：サムホイールは 1 回転で数十件の通知が来る。毎回書くとログが埋まる。二重動作の確認には「届いていたが送らなかった」ことが 1 行あれば足りる

### 2.3 実行前に捨てたボタン操作を記録する

- `Invalidate` は `actions` を空にする。このとき、まだ実行していない**ボタン操作**（`Cid != 0` の要素）が残っていたら、1 件につき 1 行のログを書いてから空にする

  ```
  未実行のボタン操作を破棄 CID=0053 設定=Keys Ctrl+V
  ```

- サムホイールの要素（`Cid == 0`）は、残っていた件数を 1 行にまとめる（0 件なら書かない）

  ```
  未送信のサムホイール 3 件を破棄
  ```

- 破棄の理由は書かなくてよい。直後に出る「状態 A -> B: 理由」の行で分かる
- 理由：肩代わり中にボタンを押した直後に Options+ が設定を始めると、その押下は LogiGap も実行しないまま捨てられる（Options+ が処理したかどうかは分からない）。今はこれが黙って起きるので、「押したのに何も起きなかった」の原因をログで追えるようにする

### 2.4 ログの量について

- 2.1 は押下 1 回につき 1 行なので、日常の使用で 1 日に数百行程度になる。既存の `FileLog` は日ごとのファイルと整理を持っているので、追加の対策はしない

## 3. 切り替えの通知

### 3.1 GapSession が出すもの

- 新しいイベントを追加する：`public event Action<string>? SwitchNotice;`
- 次の 2 つの時点で、通知文を渡して呼ぶ。**それ以外では呼ばない**
  1. **肩代わりの開始**：接続判定で Active に変わったとき（`Change(SessionState.Active, "接続判定: 設定の肩代わりが必要")` の箇所）
     - 文：`肩代わりを開始しました（接続から 0.18 秒）`
     - 秒数は `clock.Now - linkedAt` を、小数 2 桁の秒で書く
  2. **Options+ への引き継ぎ**：`ObserveOptions` で、**Active から** Retreated に変わったとき
     - 文：`Options+ に引き継ぎました（肩代わり 13.42 秒）`
     - 秒数は、Active になった時刻（新しいフィールドで持つ）からの経過を、小数 2 桁の秒で書く
- **起動時の接続判定で Options+ が設定済みだった場合**（Active を経ずに Retreated になる場合）は、通知しない。`startupCheck` 中に Options+ の書き込みを見て Retreated になる場合も、Active を経ていないので通知しない
- 理由：ユーザーが知りたいのは「肩代わりが始まった」と「Options+ に渡した」の 2 点だけである。切り替えが起きていないのに通知すると、通知に慣れて見落とす原因になる
- イベントを呼ぶときは、同じ文をログにも残す：`通知: 肩代わりを開始しました（接続から 0.18 秒）`
- `settings.NotifyOnSwitch`（3.2）が false のときは、イベントもこのログも出さない
  - 判定には、そのときの `settings` を使う（`sessionSettings` ではない）。理由：設定ファイルで通知を切ったら、次の接続を待たずにすぐ止まってほしいため
- `StateChanged` と同じく、ロックの中から呼んでよい。受け取る側は待たない処理（UI スレッドへの投函だけ）にする。この約束をイベントの宣言にコメントで書く

### 3.2 設定

- `GapSettings` に `public bool NotifyOnSwitch { get; init; } = true;` を追加する。JSON では `gapFiller.notifyOnSwitch` になる
- 既存の `config.json` にこの項目が無いときは、既定値の true になること。既存の設定ファイルは書き換えない
- 理由：今は実機で確かめている最中なので、既定で表示する。慣れたら設定で切れるようにする

### 3.3 Program.cs

- `gap.Session.SwitchNotice` を購読し、`Post` で UI スレッドに渡して、`icon.ShowBalloonTip(3000, "LogiGap", text, ToolTipIcon.Info)` で表示する
- `Dispose` で購読を外す（`StateChanged` と同じ扱い）
- 理由：通知アイコンは指示書B の通知（かざぐるマウスの検出など）で既に `ShowBalloonTip` を使っている。同じ仕組みにそろえる。Windows 11 では、これは通知センターのトーストとして表示される

## 4. テスト（xUnit、既存の `Harness` を使う）

少なくとも次を追加する。既存のテストは、すべてそのまま合格すること。

1. 引き継ぎ後（Active → Options+ の書き込み → Retreated）にボタンを押して離し、もう一度押すと、
   - キー入力は 1 件も出ない
   - 「押下: LogiGap は実行しない（Options+ に引き継ぎ済み）」の行が、CID と設定つきで**押下ごとに 1 行**出る（押したまま同じ通知が続いても 1 行）
2. 肩代わり中にボタンを押したまま引き継がれ、引き継ぎ後の通知にもその CID が残っているとき、実行しなかった押下の行は**出ない**。いったん離して押し直すと出る
3. 起動時の接続判定で Options+ が設定済みだった場合（Retreated から始まる）も、押下が「Options+ に引き継ぎ済み」の理由で記録される
4. 引き継ぎ後のサムホイールの通知を何件送っても、`HorizontalWheel` は呼ばれず、記録の行はそのリンクで 1 行だけ。再リンク後は、また 1 行出る
5. 肩代わり中にボタンの通知を受けて、`Pump` する前に Options+ の書き込みが来ると、キー入力は出ず、「未実行のボタン操作を破棄」の行が出る
6. 一時停止中のボタン押下は、何も記録しない
7. 通知：
   - Active になると、`SwitchNotice` が 1 回、「肩代わりを開始しました（接続から 」で始まる文で呼ばれる
   - その後の Options+ の書き込みで、もう 1 回、「Options+ に引き継ぎました（肩代わり 」で始まる文で呼ばれる。偽時計を 13.42 秒進めたとき、秒数が `13.42` になる
   - 起動時の接続判定で Options+ が設定済みなら、1 回も呼ばれない
   - `notifyOnSwitch` を false にした設定では、1 回も呼ばれない。肩代わり中に `UpdateSettings` で false にした場合も、その後の引き継ぎは通知しない
8. 設定：`notifyOnSwitch` の無い JSON を読むと true になる

`app/README.md` に次を足す（既存の構成と文体に合わせる）。

  （`app/publish` のフォルダで実行する例として書く）
