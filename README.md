# PartsTray

Windows 11 のタスクバーの右端（通知領域）に常駐する、小さな便利アプリです。

- **周辺機器の電池**：機器ごとに、残量の分だけの輪と機器の絵を出します。充電中は黄色の稲妻が付き、100% になると輪が虹色になって回ります。
  - 対象：Logi Bolt でつないだロジクールの機器と、Windows が電池の残量を読める Bluetooth 機器（ロジクール以外も可）
  - 絵：マウス・キーボード・ヘッドホン・イヤホン・ゲームパッド・その他。種類は自動で見分け、設定画面で選び直すこともできます
- **CPU・温度・メモリ**：CPU 使用率に合わせて速く回るパーティーパロットと、数字のアイコン
- **マウスジェスチャー**：右ボタンを押したまま動かして、戻る・進む・更新・閉じる・最小化（かざぐるマウス風。軌跡も出ます）
- **MX Master 4 の肩代わり**：Logi Options+ が設定を終えるまでの間だけ、ポインタの速さとボタンの割り当てを代わりに受け持ちます。MX Master 4（Logi Bolt 接続）専用で、最初は切れています

明るいタスクバーにも、暗いタスクバーにも対応しています。

名前の「PartsTray」は、通知領域（tray）に小さな道具（parts）が集まっていることと、ねじなどの小物を入れておく「部品トレー」（parts tray）を掛けています。元は **LogiGap** という名前で、ロジクールの MX Master 4 を Logi Options+ が設定し終えるまでの「すき間（gap）」を埋めるために作り始めました。機能が増えて元の名前と合わなくなったので、2026-11-20 に改名しました。`codex/` の指示書と報告は、当時の名前のまま残しています。

ロジクール（Logitech）の公式のアプリではありません。

## 使い方

Windows 11（x64）で作り、確かめています。Windows 10 では確かめていません。

### zip で受け取った人

1. **.NET 9 デスクトップ ランタイム**を入れておく。入っていない PC で起動すると、Windows が英語の案内（「You must install or update .NET to run this application.」）を出します。そこで「Download it now」を押すと、Microsoft のダウンロードのページが開きます。コマンドで入れる場合は、次のとおりです。

   ```bash
   winget install Microsoft.DotNet.DesktopRuntime.9
   ```

2. zip を好きなフォルダーに展開する（例：ドキュメントの中）。設定とログを exe の隣に書くので、「Program Files」の中は避けてください。
3. `PartsTray.exe` を起動する。「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押してください（署名のない、ネットから落とした exe には必ず出ます）。
4. 初めて起動すると、通知で案内が出ます。アイコンは、最初はタスクバーの右の「∧」（隠れているインジケーター）の中にあります。タスクバーへドラッグするか、Windows の設定の「個人用設定 → タスク バー → その他のシステム トレイ アイコン」でオンにすると、いつも表示されます。

### 自分でビルドする人

[.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0) を入れて、このフォルダーで次のコマンドを実行すると、`app/publish` に `PartsTray.exe` ができます。

```bash
dotnet publish app/PartsTray/PartsTray.csproj -c Release --self-contained false -o app/publish
```

### 設定

通知領域の温度のアイコンを左クリックすると、設定画面が開きます（右クリックのメニューの「設定…」、`PartsTray.exe` をもう一度起動、でも開きます）。設定は `PartsTray.exe` と同じフォルダーの `config.json` に保存されます。

温度のアイコンを出さない設定にすると、その場所には PartsTray のアプリのアイコンが出ます。通知領域のアイコンを全部切っても、メニューと設定の入口はなくなりません。

**最初は切ってあるもの**：マウスジェスチャーと、タイトルバー・最小化ボタン・ホイールの操作（かざぐるマウス風の機能）は、知らないうちにウィンドウの動きが変わらないよう、最初は切ってあります。使うときは、設定画面の「ジェスチャー」と「ウィンドウ・ホイール」のタブでオンにしてください。MX Master 4 の肩代わりも最初は切ってあり、MX Master 4 が見つかったときだけ設定画面に出ます。

### やめるとき

1. 右クリックのメニューで「Windows 起動時に自動起動」を外す（オンにしていた場合）
2. メニューの「終了」で終える
3. フォルダーごと消す

### 分かっている制限

- 温度は、PC によっては取れません（ACPI の温度を出さない PC）。そのときは、設定の「温度の読み方」で Core Temp を選んでください（Core Temp の起動と、共有メモリの有効化が必要です）
- ロジクールの機器の電池は、Logi Bolt の受信機につないだものだけ読めます（古い Unifying の受信機は読めません）。Bluetooth でつないだ機器は、Windows が電池の残量を読めれば表示されます
- AirPods は、Windows が電池の残量を出さないので表示されません

## 実機で分かったこと

### 機器と通信の基本
- レシーバーは **Logi Bolt（PID 0xC548）**。**MX Master 4 が dev 2**、**MX Keys S が dev 3**
- **Options+ のソフトウェアIDは 0xE**。自作アプリは **0x5** を使う
- 他のアプリの応答もすべて見える。Windows は HID の入力を、開いている全員にコピーして届けるため
- ポインタ速度は **ADJUSTABLE_DPI（0x2201）** で設定する。既定値は 1000、200〜8000 を 50 刻みで指定できる

### 抜き差し実験（2026-11-18 22:48）の時系列

| 時点 | 出来事 |
|---|---|
| 0 秒 | レシーバー検出。0〜13 秒はレシーバー自体が応答しない（ResourceError） |
| 22.7 秒 | MX Master 4 のリンク確立。直後に「再設定してほしい」通知（0x1D4B）が届く |
| +0.04 秒 | Options+ が問い合わせを開始 |
| +0.88 秒 | Options+ が DPI を **一度 1000（既定値）** に書き込む |
| +1.02 秒 | Options+ が全ボタンの **横取りを一旦 OFF**（flags=0x22） |
| +1.65 秒 | Options+ が全ボタンの **横取りを ON**（flags=0x23） |
| +2.09 秒 | Options+ が DPI を **2200** に書き込む（設定完了） |

この回は、Options+ がリンク確立から約 2 秒で設定を終えた。

### 遅かったケース（2026-11-18 23:03、sniff_quiet で記録）

| 時点 | 出来事 |
|---|---|
| 0 秒 | レシーバー検出 |
| 1.1 秒 | MX Master 4 のリンク確立（ここからマウスは動く） |
| 3.1〜16.4 秒 | Options+ がレシーバーのレジスタ 0xFC を読もうとするが、エラー（ResourceError）が返り続ける。Options+ は間隔を倍々に延ばしながら再試行する（0.5→1.1→1.7→3.0→5.6 秒…） |
| 16.7 秒（リンクから 15.6 秒後） | ようやく Options+ がマウスに話しかけ、約 1 秒で設定を終える |

**遅れの原因は、Options+ がマウスと話す前に、レシーバーの準備完了を待っていることらしい。** 待つ間隔が倍々に延びるので、レシーバーの準備が少し遅れるだけで、待ち時間が 1 分以上に膨らみうる。マウスそのものはすぐ話せる状態なので、自作アプリはリンク確立の直後に設定すればよい。この回なら、約 15 秒の空白を埋められた。

### ボタンの対応（実測）
常駐記録中に、Ctrl+C のボタン、Ctrl+V のボタンの順に押してもらった。その結果、**Ctrl+C = 進む（0x0056）**、**Ctrl+V = 戻る（0x0053）** と確定した。

### Options+ が設定し直すもの（＝空白の時間に崩れるもの）
- DPI（2200）
- ボタンの横取り：中ボタン・戻る・進む・ジェスチャー・SmartShift・ハプティックパネル（0x0052 / 0x0053 / 0x0056 / 0x00C3 / 0x00C4 / 0x01A0）
- 左右クリックの分析用通知（横取りはしない。無視してよい）
- サムホイール：横取りしたうえで反転。速度 50% は Options+ がソフトウェアで実現している
- メインホイール：通常モード（高解像度オフ・反転なし）に書き込む。これはマウスの既定値と同じ

### Options+ が読むだけで書き込まないもの（＝マウス本体に保存されていて崩れないもの）
- SmartShift オフ、ホイールの押下圧 100%（SMART_SHIFT_ENHANCED が mode=2, autoDisengage=255, torque=100 を返す）

## ユーザーの Options+ 設定（MX Master 4、スクリーンショットより）

| ボタン | CID | 割り当て |
|---|---|---|
| ホイールクリック（中ボタン） | 0x0052 | ポインタ速度を切り替え（2200 ⇔ 1100 DPI） |
| ホイール後ろのボタン | 0x00C4 | ホイールモード切替（初期値。マウス本体の機能なので肩代わりは不要） |
| 親指部の上ボタン（ジェスチャーボタン） | 0x00C3 | PrintScreen |
| 親指パネル（ハプティック） | 0x01A0 | Win + ↑ |
| 進む（前側） | 0x0056 | Ctrl + C |
| 戻る（後側） | 0x0053 | Ctrl + V |
| サムホイール | — | 水平スクロール、速度 50%、方向は反転 |

キーボード（MX Keys S）は初期設定のままなので、対象外とする。

ジェスチャーは Options+ ではなく、かざぐるマウスで使っている。かざぐるマウスは Windows 11 に対応していないため、設定済みの機能をすべてこのアプリで再現する（[設定まとめ](data/kazaguru/設定まとめ.md)）。

## 実装の進め方

- 実装はユーザーが起動する Codex が行い、Claude がレビューする。指示書は `codex/` に置く
  - [指示書A：つなぎ役](codex/指示書A_つなぎ役.md)：常駐アプリの土台と、Options+ が設定するまでの肩代わり
  - [指示書B：ジェスチャー](codex/指示書B_ジェスチャー.md)：かざぐるマウスの機能の再現（A の完成後に渡す）
- 言語は **C# / .NET 9**（インストール済み）。常駐とマウスフックの安定性を優先した
  - Python は、ガベージコレクションなどで処理が一瞬止まりうる。マウスフックが Windows のタイムアウトに引っかかると、フックを外されてしまう
  - exe 1 つで動き、Python の実行環境が要らない
- いまある Python のツール（probe / sniff）は調査用として残す。本体の HID++ 実装は、これを手本に C# で書き直す

## 本体アプリの設計方針（案）

1. MX Master 4 のリンク確立（接続通知 0x41）を検知したら、すぐ DPI 2200 を書き込み、上記のボタンを横取りする
   - サムホイールも Options+ と同じく横取りして、**反転・速度 50% の水平スクロールを自前で再現する**（2026-11-18 ユーザー決定。妥協しない）
   - 撤退後、Options+ がサムホイールを設定し直さないまま一定時間たったら、サムホイールを通常モードに戻す（回しても動かない状態を残さないため）
2. **Options+（swid 0xE）の setCidReporting 応答を 1 つでも見たら、ボタン処理を即座に止める。** 設定は戻さない。Options+ は最初に横取りを一旦 OFF にするので、そこで止まれば二重実行は起きない
3. 撤退の合図は「Options+ の最初の通信」ではなく「setCidReporting」にする。遅い場合に、Options+ が問い合わせだけを先に始めている可能性があるため（常駐記録で確認する）
