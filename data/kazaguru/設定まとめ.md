# かざぐるマウスの設定まとめ（2026-11-18 読み取り）

- 元の場所：ダウンロードして展開した `KazaguruMouse64_1.67b` フォルダー（バージョン 1.67b、64bit 版）
- 設定ファイル：同じフォルダの `Kazaguru.ini`。写しを [Kazaguru.ini](Kazaguru.ini) に置いた
- ini にはコマンドが番号でしか書かれていない。番号と名前の対応は、Kazaguru.exe の中にある「(番号, コマンド名)」の表から割り出した。表は先頭が「32 → 通知アイコン メニュー」、末尾が「107 → 5 つ進む」で、並びは「番号が先、名前が後」と確定している。exe はデータとして読んだだけで、実行も変更もしていない
- **ユーザーの希望：設定してある機能はすべて再現する。特に、右ドラッグ中に描かれる緑・赤の軌跡（らくがき代わりに使っている）は必ず再現する**

## マウスジェスチャー（右ボタンを押しながら動かして離す）

| 動き | 番号 | コマンド |
|---|---|---|
| ← | 1 | 戻る |
| → | 2 | 進む |
| ↑↓ | 3 | 更新 |
| ↓→ | 6 | 閉じる（ブラウザのタブなど） |
| ↓← | 109 | 最小化（ウィンドウ） |

ジェスチャーの動作設定：

| 項目 | ini のキー | 値 |
|---|---|---|
| 1 ストロークと認識する距離 | GestureRange | 10 px |
| 入力開始のタイムアウト | GestureTimeout | 1000 ms（右ボタンを押してから 1 秒動かさなければ、普通の右ドラッグになる） |
| 軌跡の描画 | DrawGesStroke / GesStrokeWidth | あり。幅 3 px |
| 軌跡の色 | ValidGesStrokeColor / InvalidGesStrokeColor | 有効 65280 = 緑 (#00FF00)、無効 255 = 赤 (#FF0000)。値は Windows の COLORREF（0x00BBGGRR） |
| 軌跡の描画方法 | GesDrawingType | 2（方式の中身は未解読） |
| 連続実行 | EnableGesRapidFire | ON。ジェスチャー中に左クリックするたびに、入力中のコマンドを実行する |
| コマンド名のツールチップ | ShowBalloonTip / ShowBalloonDelay | ON。ジェスチャー中に 1000 ms 静止すると、入力中のコマンド名を表示する |
| ジェスチャーを有効にする場所 | GestureFlags=382, AllowFlagsInIE=7, AllowFlagsInMozilla=7, AllowFlagsInWindow=15 | ブラウザ・一般ウィンドウ・タイトルバー・タスクバーボタンなど、ほぼ全部 |
| エクスプローラでの開始位置 | AllowLevelInExplorer=1, IgnoreIconLabelMargin=1 | 背景と、選択されていない項目の上から開始できる。選択中の項目の上からは開始しない（ファイルの右ドラッグを邪魔しないため）。詳細表示などの文字の余白は背景とみなす |

## タイトルバーの操作

| 操作 | ini のキー | 番号 | コマンド |
|---|---|---|---|
| タイトルバーを Shift+クリック | S+LC_1 | 201 | 常に最前面に表示（切り替え） |
| タイトルバーを Ctrl+クリック | C+LC_1 | 202 | 実行ファイルのフォルダを開く |
| タイトルバーを中央クリック | MC_1 | 203 | ウィンドウを閉じる |
| 最小化ボタンを右クリック | RC_3 | 206 | 通知アイコン化（タスクトレイにしまう） |

最前面化したときの通知音と強調表示は、どちらも OFF（PlaySoundWithTopMost=0, HighlightTopMost=0）。

## ホイールなど

| 設定 | ini のキー | 値 | メモ |
|---|---|---|---|
| カーソル下のウィンドウをスクロール | ScrollAlways=1 | ON | Windows 11 の標準機能（「非アクティブ ウィンドウをスクロール」）が ON になっている（レジストリ MouseWheelRouting=2 で確認済み）。自作では横取りせず Windows に任せる |
| カーソル位置に入力フォーカスを合わせる | SetFocus=1 | ON | ホイールを回したとき、カーソル下の部品に入力フォーカスを移す |
| 垂直スクロールバー上でホイールを回す | ScrollExOnVScrlBar=54 | 高速スクロール | スクロール量の正確な倍率は不明 |
| 無効状態のウィンドウもタイトルバーで移動できる | MoveDisabledWindow=1 | ON | ダイアログ表示中で操作できない親ウィンドウも、ドラッグで動かせる |
| プロセスの優先度を上げる | PriorityClass=1 | ON | フックの反応を良くするため |
| タスクバーボタン・通知アイコンのドラッグ並べ替え | MoveTaskButton=1, MoveTrayIcon=1 | ON | XP/Vista 専用で、Windows 11 では効かない。標準で並べ替えできるので再現しない |
| ボタンでのスクロールのキーリピート | EnableAutoScroll=1 | ON | スクロールのコマンドをボタンに割り当てたときだけ効く。割り当てがないので実質無関係 |

| 操作 | ini のキー | 番号 | 動作 |
|---|---|---|---|
| トレイアイコンを左クリック | IconClick | 33 | オプション（設定画面）を開く |
| トレイアイコンを右クリック | IconRClick | 32 | メニューを出す |
| トレイアイコンを中央クリック | IconMClick | 34 | 一時停止（切り替え） |

## 「たまにスクロールが一切効かなくなり、かざぐるマウスを再起動すると直る」問題

ユーザーが困っている現象。推測される仕組み：

- かざぐるマウスは「カーソル下のウィンドウをスクロール」を実現するため、ホイール入力を低水準フックでいったん横取りしている。そのうえで、各アプリに注入した DLL（Kazahook.dll）や 32bit 用の補助プロセス（Kazawow64.exe）を通して、対象のウィンドウへ届け直す
- この届け直しの経路が何かの拍子に壊れると、横取りだけが続き、ホイール入力が消えてしまう。再起動で経路が作り直されるので直る

自作での対策：

1. 「カーソル下のスクロール」は Windows 標準に任せ、ホイール入力は原則として横取りしない
2. 例外的に横取りする場合（スクロールバー上の高速スクロール）は、Windows 標準の入力経路（SendInput）で必ず送り直す。他のアプリへ DLL を注入しない
3. フックの処理を極力短くし、Windows にフックを外されないようにする。外されたことを検知したら付け直す
