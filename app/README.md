# PartsTray（指示書 A・B・C・D・E・F・G・H）

> 2026-11-20 に **LogiGap から PartsTray に改名**しました。この文書の中の名前も PartsTray に置き換えています（`codex/` の指示書と報告は当時の LogiGap のまま）。改名で変えたことは下の「改名とアプリのアイコン」の節にあります。

MX Master 4 を Logi Bolt 経由で使用し、再接続から Options+ の設定開始までを肩代わりする Windows x64 常駐アプリです。右ドラッグのジェスチャーと緑・赤の軌跡、タイトルバー操作、通知アイコン化、スクロールバー上の高速スクロール、無効ウィンドウの移動にも対応します。本体は C# / .NET 9 / WinForms / P/Invoke を使用し、UI Automation は Windows Desktop の WPF 参照で利用します。新しい NuGet パッケージはありません。

指示書 A のレビュー 1、指示書 B と B レビュー 1 の修正 1〜7、指示書 C と C レビュー 1 の修正 1・2、指示書 D のサムホイールのフック方式を維持し、指示書 E の横スクロール記録と滑らか化、F の Options+ 検出、G の残存横取り解除、H の再起動判定を反映しました。復元済みの環境で `--no-restore` を指定したビルドは警告 0・エラー 0、テストは全 295 件合格（H 以前の 271 件＋追加 24 件、失敗 0・スキップ 0）を確認しました。実機動作はレビュー後の確認対象です。

この実装作業では **アプリを一度も起動せず、マウスフックの導入、オーバーレイ表示、HID・SendInput・レジストリ操作も実行していません**。検証はビルドと偽送受信・偽時計・偽ヒットテストの xUnit テストのみです。実機確認はコードレビュー後に行ってください。

## 配る前の最終確認での直し（2026-11-20、Claude）

- かざぐるマウス由来の操作を、既定では切るようにした：`gesture.enabled`、`titleBar` の 4 つ（`None`）、`wheel.fastScrollOnScrollBar`・`wheel.focusUnderCursor`、`moveDisabledWindows`。受け取った人の PC で、タイトルバーの中クリックでウィンドウが閉じるなど、知らないうちに動きが変わるのを防ぐため。設定ファイルに値が書いてあればその値を使うので、作者の PC の動きは変わらない。ジェスチャーのテストは、変える前の既定（全部オン）を `GestureTestSettings.AllOn` でそろえている
- 初めての起動（`config.json` がまだない）では、2 秒後に「アイコンは ∧ の中にあります」という通知を出す（`Program.cs` の `ShowFirstRunGuide`）。Windows は新しいアプリの通知アイコンを最初は隠すので、何も起きないように見えるため
- .NET 9 デスクトップ ランタイムがない PC では、.NET の起動部分が英語のダイアログ（「You must install or update .NET to run this application.」、「Download it now」「閉じる」）を出すことを確かめた（試し用のコピーで、存在しない版の .NET を求めるように書き換えて起動）。アプリ自身は .NET がないと動けないので、日本語の案内は出せない。トップの README に入れ方を書いた
- 設定ファイルなしの初めての起動を、配る zip と同じ中身で試した：設定ファイルが既定値で作られ、肩代わりは切れた状態で始まり、電池・CPU・温度・メモリのアイコンが出た。エラーはなし

## 改名とアプリのアイコン（2026-11-20、Claude）

- フォルダー・プロジェクト・名前空間・exe を `PartsTray` にした（`PartsTray.sln`、`PartsTray/`、`PartsTray.Core/`、`PartsTray.Tests/`、`PartsTray.exe`）
- 二重起動を防ぐ名前（`Local\PartsTray.Instance.…`・`Local\PartsTray.Show.…`）と、自動起動の登録名（`PartsTray`）も変えた。起動したとき、前の名前（`LogiGap`）で自動起動を登録していたら、今の exe で登録し直して前の登録を消す（`Program.cs` の `MigrateAutoStart`）
- `config.json`・`logs/`・`state/` は exe と同じフォルダーにあるので、同じフォルダーに置き換えればそのまま引き継がれる
- Windows は通知領域のアイコンを「exe のパス＋番号」で覚えるので、exe の名前が変わると、アイコンは一度すべて隠れたアイコンの中に入る。設定で一度だけ表示し直す
- マウスの電池のアイコンの説明の 2 行目は「肩代わり: 肩代わり中」などにした。肩代わりを切っているとき（配った人の既定）は、2 行目も、右クリックのメニューの状態の行も出さない
- アプリのアイコン（`PartsTray/PartsTray.ico`）：暗い角丸の板に、枠いっぱいの虹の輪（上から時計回りに赤→黄→緑→水色→青→紫）と、白いキーボードとマウス（ユーザーが見本 E1R を選んだ）。16〜256 ドットの 9 つの大きさが入っている。exe・設定画面・温度を出さない設定のときの通知領域の本体のアイコンに使う（`AppIcon.cs`）

## 残量 100% の虹の輪（2026-11-20、Claude）

- 残量が 100% の機器は、緑の輪の代わりに虹の輪にして回す（ユーザー：「パーティーパロットが虹色に光るなら、こっちも虹色に光ればええやん」）。見本の A（輪全体の色が順に変わる）と B（虹の帯が回る）から B を選んだ。A は一瞬、赤やオレンジ一色になり、電池切れ間近の色と見分けにくいため
- 充電中かどうかに関係なく、残量が 100% なら虹。充電完了の稲妻はそのまま付く。切断中（薄い表示）は回さない
- 設定：`battery.rainbowWhenFull`（既定 true）、`battery.rainbowLapMs`（虹が 1 周する時間、既定 1100、200〜10000）。設定画面の「通知領域のアイコン」の電池の欄にもある。既定の速さは、見本（1 周 1.9 秒）の 1.5〜2 倍というユーザーの指定から
- 描き方：`BatteryIcon.DrawRainbow` で、細かい弧を 90 本つないで描く。色は `Palette.Rainbow`（彩度 0.85・明度 1）を `Palette.ForTaskbar` で背景との差 3:1 以上にしたもの。1 周を 16 コマにし、一度アイコンにしたコマは取っておいて使い回す（`BatteryModule.RainbowFrame`。捨てるのはアプリを終えるときだけ）。回すタイマーは、回る輪があるときだけ動く
- CPU：2 台（マウスとキーボード）を回して、虹あり・なしを 5 秒ずつ 3 回比べると、増えたのはコア 1 つのおよそ 1〜2%（測るたびにばらつく。オウムの速さが CPU 使用率で変わるため）

## タスクバーのクリックで止まらないようにした（2026-11-20、Claude）

- ユーザー：「タスクバーをどこでもいいのでクリックするだけで止まる」。並べ替え中の描き替えを止める仕組み（`TrayInteraction`）が、タスクバーのどこで押しても「並べ替え中」とみなしていた
- 押し始めの位置が、通知領域のアイコン（UI Automation の AutomationId が `NotifyItemIcon`）の枠の中のときだけ止めるようにした。枠の一覧は押した瞬間に別スレッドで取る（12〜30ms）。取り終わるまでの一瞬だけは止める。隠れているアイコンの小窓の上で押したときは、今までどおり止める
- 「この点に何があるか」を UI Automation で聞く方法（`AutomationElement.FromPoint`）は、タスクバーの中までは答えなかった（11/20 実機）

## 数人に配るための変更（指示書 N）

この節が現在の仕様です。J・K・L・M の節には過去の調整の記録も残しています。既存の設定キーの意味と、明示された設定値は維持します。

**肩代わりの既定と表示条件**

`gapFiller.enabled` の既定は `false` です。すでに `true` が書かれている利用者の設定は有効のままです。DPI・ボタン割り当て・サムホイールの既定値は変えていません。「マウスの肩代わり」タブは、設定が有効か、起動後に MX Master 4 を検出した場合に表示します。先頭に MX Master 4（Logi Bolt 接続）専用で、Options+ が動き出すまで働くことを表示します。隠れたタブの設定は保存や「すべて既定に戻す」でも保持します。

無効時は肩代わりの照会・書き込み・ボタン入力・サムホイール送信を行わず、「つなぎ役を一時停止」のメニューも隠します。受信機の接続監視とオープン、独立した swid 7 の電池・名前・種類の読み取りは続きます。電池自体の有効・無効は従来どおり `battery` で指定します。

検出は WPID `0xB042` の接続通知、従来の GapSession の起動識別、電池照会で得た完全一致名 `MX Master 4` を使い、起動中は一度検出した事実を記憶します。要求は増やしません。肩代わりと電池の両方が無効で接続通知もない場合は検出できません。

**機器の種類と設定**

Bluetooth は、名前による手動指定 → 同じ Container ID の HID 互換 ID → Bluetooth Class of Device → 名前の手掛かり → その他の順で判断します。HID は存在しない部品も別に列挙し、接続判定には存在する HID・音声エンドポイントを使います。Class of Device の音声機器だけは、AirPods・Buds・WF-・Earbuds・イヤホンという名前ならイヤホンにします。ロジクール以外のマウス・キーボードも、Windows が電池値を提供すれば対象です。

「通知領域のアイコン」の電池欄の「機器の種類」で、「自動（いまは〇〇）」か6種類を選べます。自動はその名前の指定を削除します。画面を開き直すか適用すると一覧を読み直します。同名の機器は同じ指定を共有し、見つかっていない名前の設定は保持します。JSON では次のように指定します（名前は大文字・小文字も含めて一致）。

```json
{
  "battery": {
    "kinds": {
      "AirPods 4": "earbuds",
      "自分のコントローラー": "gamepad"
    }
  },
  "monitor": { "taskbarTheme": "auto" }
}
```

`battery.kinds` の既定は空です。値は `mouse` / `keyboard` / `headphones` / `earbuds` / `gamepad` / `other` のみで、`auto` は保存値に使いません。ロジクールの機器にも手動指定を適用できます。

電池枠は12個を起動時に確保します。マウス11、キーボード12、ヘッドホン13、イヤホン14、ゲームパッド15、その他16を固定枠とし、同じ種類の2台目以降を名前順で17〜22へ入れます。同名ならID順です。本体1・オウム2・CPU9・メモリ10と電池11〜13は維持します。`HiddenWindowManager` が後から生成するウィンドウ用アイコンは23以降です。切断中はヘッドホン・イヤホン・ゲームパッドを隠し、マウス・キーボード・その他は最後の値を薄く表示します。追加枠が足りない場合は名前順で入る分だけ表示します。

絵は11/20に決まった形です。マウスとヘッドホンは維持します。イヤホンは左右対称の軸付きで全体を滑らかにし、中央2列を透明、その両隣だけくっきりさせます。ゲームパッドは本体と左右の握りをくっきり描き、左の四角いスティック穴と右の四つのボタン穴を縮小後に抜きます。キーボードは今回の例外として描き直し、2段の粒と6ドットのスペースキーを縮小後に抜きます。その他はくっきりした横向きの電池です。16・20・24・32pxでも指定と同じ式を使い、キーボードの穴は本体の内側だけに限定します。

**明るいテーマ**

`monitor.taskbarTheme` は `auto`（既定）/ `dark` / `light` です。設定画面の「タスクバーの明るさ」でも変更できます。`auto` は HKCU の `Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` にある `SystemUsesLightTheme` を5秒ごとに読み、モニターと電池へ同時に通知します。並べ替え中は描画を保留し、終了後の更新で反映します。

背景を暗い `#1C1C1C`、明るい `#F3F3F3` として、数字・電池の輪・機器の絵・稲妻の色を WCAG の式で検査します。3:1 未満なら HSL の色相・彩度を保ち、明度だけを補正します。ただし白・灰色（彩度 0）は、3:1 ぎりぎりの灰色だとくすんで見えるので、明るい背景ではほぼ黒の `#1A1A1A`（`Palette.LightForeground`）にします。機器の絵・白い数字・オウムがこの色になります（11/20 Claude のレビューで変更）。3:1 以上の色はそのままです。暗い背景の輪だけ従来の Brighten を行い、明るい背景では行いません。滑らかな輪郭の不透明度と切断時の薄さは維持します。明るい背景の実測色は未確認です。

GIFの黒いふちと目は暗いテーマでは従来どおり透明にし、明るいテーマでは残します。切り替え時はコマと縮小キャッシュを作り直します。RunCat の影絵の塗り替え方は維持します。

## 設定ウィンドウ（指示書 M）

通知領域の右クリックメニューで、状態のすぐ下にある「設定…」を選ぶと「PartsTray の設定」が開きます。本体（温度）のアイコンの左シングルクリック、または PartsTray の 2 つ目の起動でも開きます。すでに開いている場合は同じ画面を前に出し、最小化されていれば戻します。ダブルクリックと中クリックの動作は従来どおりです。

画面を閉じると破棄し、次に開くときはその時点の `config.json` を読み直します。読み込みに失敗した場合は理由を表示し、「既定の設定で開く」「やめる」を選べます。既定の設定で開くだけでは不正なファイルを上書きしません。

各タブはスクロールできます。ジェスチャーの形は `LRUD`・矢印・両者の混在で入力でき、編集後は矢印で表示します。方向ボタンと「1 つ消す」でも編集できます。行の追加・削除ができ、同方向の連続、重複、1〜64 文字の範囲外、256 行超過は赤く表示して保存を止めます。色は見本のボタンまたは `#RRGGBB` の入力欄で指定し、不正な色は赤く表示します。

「出さない機器」ではチェックした名前を非表示にします。見つかっていない保存済みの名前にも「（今は見つかっていない）」を添えて残し、チェックを外して表示対象へ戻せます。名前は手入力でも追加できます。機器名は大文字・小文字や空白も含めて一致させてください。

「OK」は保存して閉じ、「適用」は保存して画面を残します。「キャンセル」や × で閉じるとき、変更があれば「保存」「保存しない」「キャンセル」で確認します。保存には既存の `AppSettings.Validate()` と `AppSettings.Save()` を使い、外部でファイルが変更されていた場合は上書きの確認を表示します。読み書きの失敗は画面に理由を表示します。

保存後は既存の約 1 秒ごとの設定再読込で反映します。ポインタ速度・ボタン割り当て・サムホイールの方式は従来どおり次の接続から有効です。「肩代わりしない」は該当ボタンのキーを `buttons` から削除します。`GapSession` がキーのないボタンの横取り設定を送らずにスキップすることを確認し、5 ボタンそれぞれについて偽の送受信によるテストも追加しました。

自動起動だけはチェック直後に同じユーザーの Run キーへ反映し、トレイメニューと同じ値を読み書きします。キャンセルや既定に戻す操作では元に戻りません。「すべて既定に戻す」は確認後に画面の値だけを戻し、OK／適用までは保存しません。画面に出さない `mouseWpid`・`ownSwid`・`battery.pictureHeight` と未知の最上位項目 `Modules` は保持します。

従来の「設定ファイルを開く」「ログフォルダを開く」メニューも残っています。`config.json` を直接書き換える方法も引き続き使用できます。

M で残した `// 要確認:` は次の 8 箇所です。

1. `SettingsWindow.cs`：96 DPI 基準の初期サイズを 576×512 にし、125% で約 720×640 を目指す。125%・150%・200% と混在 DPI の実機確認が必要。

3. `SettingsWindow.Mouse.cs`：均等時間が 0 以外で間隔未満になったら、時間を間隔まで引き上げる。
4. `SettingsWindow.Icons.cs`：`lowHot < lowWarn` を満たすため、赤は 1〜99%、オレンジは 2〜100% とし、変更した値にもう片方を追従させる。Validate が受け付ける組み合わせはすべて選択可能。
5. `SettingsWindow.Icons.cs`：非表示機器の名前を入力したまま OK／適用した場合も追加し、入力を失わないようにする。
6. `SettingsText.cs`：アプリ名の複数行入力では空行と行頭・行末の空白を除去する。拡張子の強制は既存 Validate に合わせて行わない。

## サムホイールの設定（指示書 D）

`config.json` の `gapFiller.thumbWheel` に次を指定します。

```json
"thumbWheel": { "mode": "hook", "speedPercent": 50, "directionSign": 1 }
```

| `mode` | 動作 |
|---|---|
| `hook`（既定） | 本来の横スクロールをフックで受け取り、向きと速度を変えて送り直します。適用の最後に THUMB_WHEEL を照会し、横取りが残っているときの解除だけは書き込みます（指示書 G）。 |
| `divert` | 従来どおり HID++ の setReporting(1,1) で横取りし、回転通知から入力を送ります。読み戻しと、必要な場合の THUMB OFF の後片付けを行います。 |
| `off` | サムホイールには何もしません。THUMB_WHEEL の書き込み・読み戻し・後片付けも行いません。 |

`mode` は大文字小文字を区別し、変更は次の接続から有効です。`speedPercent` は 0〜100（既定 50）、`directionSign` は 1（Options+ の「反転」オンと同じ向き）または -1（その逆）です。この 2 項目は保存後約 1 秒で即時反映し、端数はリセットします。両方式で同じ値を使います。旧 `divert` キーは廃止しました。古い設定に `"divert": false` だけが残っていても無視され、既定の `hook` になります。互換の読み替えは行いません。

既定を `hook` にした理由は、実機で横取り方式から Options+ に引き継いだ直後にサムホイールが停止したためです。

| 11/19 の観察 | 横取りあり | 横取りなし |
|---|---|---|
| Options+ 設定前の横取り回転通知 | 約 800 件 | 0 件 |
| Options+ のサムホイール設定・ホイールモード設定 | 各 3 回やり直し | 各 1 回 |
| 引き継ぎ直後 | カクついて停止、クリックで復帰 | すぐ正しい向きで動作 |

橋渡しは肩代わりの開始から、Options+ のサムホイール設定応答を観察するまで続きます。最初の DPI 設定による引き継ぎだけでは止めません。サムホイール設定までの約 1.3 秒にも向き・速度を維持するためです。長くても引き継ぎ後 `cleanupDelaySeconds` 秒までで終了します。リンク切断、レシーバー切断、新しい接続、つなぎ役の一時停止・再開でも終了します。ジェスチャー側の一時停止・Kazaguru 動作・入力ワーカー異常とは独立しています。

フックには機器識別がないため、橋渡し中はほかの機器の横スクロールも同じく反転・減速されます。他のアプリが送った入力（injected）は対象外です。PartsTray が送った横スクロールは `KeyStroke.ExtraInfo` の印で除外し、再度橋渡ししない設計です。この印が実際のフックまで保持される前提は単体テストで確かめられないため、実機で再送ループや二重スクロールがないことを確認してください。マウスフックが外れている間は、マウス本来の向き・速さになります。

ログの `サムホイール: フック方式で橋渡しを開始（向き反転・速度 50%）` が開始です。終了時には下記 E の形式で集計します。すでにフックで元の入力を止めた分は、終了後もキューから送ります（つなぎ役の一時停止中だけ破棄）。その残り分は終了ログの集計に含まれません。`サムホイール送信失敗: ...` は橋渡し 1 回につき 1 行で、HID 適用は継続します。

D で追加した `// 要確認:` のうち、`Protocol.cs` の反転符号の実機確認、`GapSession.cs` の終了後キューにも送信失敗の記録済み状態を保持する判断は維持しています。成功した非ゼロ送信だけを件数・例に記録する判断は E の受け取り・送信別の集計に置き換えました。`NativeWheelTests.cs` と `ProtocolTests.cs` で変換・状態遷移・期限・設定再読込・送信失敗・HID 待機中の処理・ロックを待たない入口を検証します。

## 横スクロールの記録と滑らか化（指示書 E）

`gapFiller.thumbWheel.smoothMs` は hook 方式の 1 段ぶんを分割して送る時間（既定 40ms、0〜200）、`smoothIntervalMs` は送信間隔（既定 8ms、4〜50）です。`smoothMs` が 0 でなければ間隔以上にします。`smoothMs: 0` は分割せず、従来どおり全量をすぐ送ります。速度・方向の計算は変えていません。`divert` には滑らか化を適用しません。

| 実機で観察した入力 | マウス本来の横スクロール | Options+ の回転通知 |
|---|---|---|
| 1 回転の細かさ | 20 段、1 段 ±120 | 120 単位、本来の 1 段は 6 単位ぶん |
| 通知間隔・量 | 間隔は未測定 | 主に 4〜16ms、1 回 1〜4 単位 |

粗い 1 段を小さく分けることで飛び飛びの動きを減らします。50%・40/8 の例では、量 60 を 0・8・16・24・32ms に 12 ずつ送り、初動を遅らせず合計を保ちます。同方向の追加入力は残量と合わせて再分割し、逆方向の入力は古い方向の残量を破棄します。遅延時も一度に追いつこうとせず 1 回分だけ送ります。Options+ が実際に画面へ送る量・間隔は未測定なので、速さの一致は記録後に調整します。

短い待ちには高精度待機タイマーを使い、利用できないときはアプリログに 1 回警告して通常の待機に戻ります。実際の間隔は OS の実行状況にも依存します。橋渡し終了後も残量を送り切りますが、一時停止と設定再読込では残量を破棄します。

記録は最上位の `"diagnostics": { "wheelTrace": true }` で有効にします。既定は false で、普段は false にしておいてください。exe の隣の `logs/wheel_yyyyMMdd.log` に UTF-8 で追記します。日付は書き込み時点の日付です。フックではキュー投入だけを行い、専用背景スレッドが約 250ms ごとに書き込みます。false に戻すと残りを書いて停止し、通常終了時も残りを書きます。

```text
# 横スクロール記録 開始 2026-11-19 17:10:41.000 列: 時刻 前からの間隔ms 量 送り元 flags extra 横取り
17:10:41.234 +8.1 -120 Device flags=00 extra=0 taken=Bridge
```

各列は、フックで受け取った時刻、直前の記録からの間隔（ms、最初は +0.0）、符号付きの横スクロール量、送り元、16 進の flags・extra、横取りした処理です。時刻と間隔はフックの Stopwatch 時刻を基に換算します。`taken=None` は素通し、`Gesture` はジェスチャー、`Bridge` は橋渡しによる抑止です。

縦ホイール（WM_MOUSEWHEEL）も記録し、その行だけ行末に `wheel=V` を付けます。横スクロールの行の形は変わりません。11/19 20:01 に Options+ を再起動した後、Options+ がサムホイールで画面を横に動かしても、横スクロールの記録が 1 件も増えませんでした。Options+ が横スクロールの代わりに縦ホイール（Shift 付きなど）を送っていないかを確かめるために足しました。

送り元は `extra` が LGAP 印なら `PartsTray`、それ以外で injected フラグがあれば `Injected`、それ以外を `Device` と分類します。PartsTray 自身の送信も記録します。`Injected` だけでは Options+ などの送信アプリ名までは特定できません。回転通知の別記録と時刻を照合してください。

待機キューは 20,000 件を上限とし、あふれた分は `# 混雑: n 件を捨てた` と記録します。アプリの 1 回の起動で合計 200,000 件に達すると記録を停止し、設定を再有効化しても上限をリセットしません。書き込み失敗はアプリログに 1 回記録してその記録を停止し、false→true で再試行します。入力判定は継続します。開始・終了件数と上限到達もアプリログに残します。

橋渡し終了時の新しいログは次の形式です。

```text
サムホイール: 橋渡しを終了（Options+ がサムホイールを設定） 受け取り 1 件（合計 120）、送信 1 件（合計 -12）、元の量の例 [120]
```

受け取りは変換結果が 0 でない入力の件数・元の量の合計と最初の 5 件の例、送信は成功した分割送信の件数・送った量の合計です。終了時点の集計なので、その後に送り切る残量は含みません。送信に失敗した分は送り直さず、送信の集計にも含めません。

E で追加した `// 要確認:` は、`WheelSmoother` を smoothMs=0 で直接使う場合の分割数を 1 とすること、高精度タイマーの終了待ちがタイムアウトした場合の解放延期、記録上限を再有効化でリセットしないこと、記録の書き込み失敗時の停止・再試行方法の 4 件です。

最初の実機確認では記録を有効にし、hook・50%・40/8 でサムホイールを両方向へ回して、肩代わり中の初動・細かさと引き継ぎ時の連続性を確認してください。ログで `Device taken=Bridge` と、それに続く小分けの `PartsTray` の量・間隔を確認し、Options+ 引き継ぎ後の記録と比較します。回転方向の切り替え、一時停止時に残量が流れないこと、記録の無効化・終了時の書き出しも確認し、測定後は記録を false に戻します。

`WheelSmootherTests.cs`、`WheelSettingsTests.cs`、`WheelTraceTests.cs` と `NativeWheelTests.cs` の追加分で、分割・方向反転・遅延・設定検証・文化に依存しない記録形式・引き継ぎ後の残量・送信失敗を検証します。既存テストは SmoothMs=0 を明示して送信量の期待値を維持し、ReplayTests の全期間のキー入力・ホイール送信ゼロの検証も維持しています。

## Options+ の検出（指示書 F）

swid が 0 でも 5 でもないマウスの応答のうち、setCidReporting・setThumbwheelReporting・setSensorDpi のどれかを、Options+（またはほかのソフト）の設定として扱います。そのどれかを見たら、PartsTray は引き継ぎます。

以前は swid 14（0xE）だけを見ていました。しかし Options+ の swid は、エージェントの起動などで変わります。

| 記録ツールで確認した時刻（11/19） | Options+ の swid |
|---|---|
| 14:25 | 0xA |
| 14:27 | 0xC |
| 16:17 と 19:18 以降 | 0xB |
| 16:24〜17:10 | 0xE |

swid 0xB のときは、Options+ が設定を始めても PartsTray が気づかず、肩代わりを続けました。引き継ぎの通知も出ませんでした。Options+ 以外のソフトがこれらの設定を書いた場合も、設定の取り合いを避けるために引きます。

- 状態の変化のログには、送り元の swid が `Options+ 設定開始（swid=B）: setSensorDpi` の形で残ります。
- `gapFiller.optionsPlusSwid` は廃止しました。古い設定に残っていても無視されます。

## 残ったサムホイールの横取りを解除（指示書 G）

11/19 の実機では、Options+ が停止してもサムホイールの横取りがマウス側に残り、hook の肩代わり中に本来の横スクロールが出ませんでした。

| 時刻 | 観察したこと |
|---|---|
| 19:21:36〜19:32:50 | Options+ が横取りを設定し、その後停止。PartsTray は hook で肩代わりを開始したが横取りが残った。 |
| 19:34:19〜33 | HID++ の回転通知は約 600 件、本来の横スクロールは 0 件で動かなかった。 |
| 19:34:33〜38 | Options+ の設定途中で横取りが外れて横スクロールが戻ったが、サムホイール設定を 4 回やり直した。 |

hook では適用の最後に getThumbwheelStatus（fn1）を 1 回照会します。先頭バイトの bit0 が 1 なら setThumbwheelReporting(0, 0)（fn2）で横取りを解除し、反転なしの本来の横スクロールに戻します。方向と速度は既存の橋渡しで変換します。横取りが残っていなければ書き込みません。書くのは解除だけで、横取りを有効にする書き込みは行いません。off は照会も書き込みも行わず、divert の適用・読み戻し・後片付けは従来どおりです。

照会の応答前、または解除の送信前に Options+ が設定を始めた場合は解除しません。hook の解除は PartsTray による横取りの所有として記録しないため、引き継ぎ後の後片付けでも THUMB_WHEEL には触れません。

| ログの例 | 意味 |
|---|---|
| `横取りが残っていたので解除する（01 01）` | 横取りを検出。続く `THUMB_WHEEL 残りの横取りを解除` の送信・OK 応答と `適用完了` で解除完了を確認します。途中で引き継いだ場合は解除を送りません。 |
| `横取りは残っていない（00 02）` | 横取りなし。指が触れていることを示す 2 バイト目の bit1 では解除せず、書き込みなしで適用を完了します。 |

G で追加した `// 要確認:` は、応答パラメーターが 2 バイト未満なら横取りなしとして扱い、解除を書き込まない判断の 1 件です。`RemainingThumbDiversionTests.cs` で残存あり・なし、引き継ぎの前後、off・divert、解除後の後片付け、状態ビットの判定を検証します。

最初の実機確認では、レシーバーを抜き差しせず Options+ が停止して横取りが残った状態で hook の肩代わりを開始し、上記の解除完了ログと、サムホイールで横スクロールできることを確認してください。続けて Options+ に引き継ぎ、回し続けても停止・カクつきがなく、クリックせず使い続けられることを確認します。

## Options+ の再起動を見分ける（指示書 H）

11/19 の実機では、停止前の Options+ が残した横取りを、再起動後の Options+ が設定済みである証拠と誤認して撤退しました。

| 時刻 | 観察したこと |
|---|---|
| 19:49:09.97〜11 | Options+ の設定を見て引き継いだ後、エージェントを停止。ボタンとサムホイールの横取りが残った。 |
| 19:49:15.1〜15.99 | エージェント再起動でリンクが再接続。`divert=1 Options+=True previousActive=False` を設定済みと誤認した。 |
| 19:49:15〜30.04 | 新しい Options+ が設定を始めるまで約 15 秒、ボタンもサムホイールも処理されず、回転通知約 950 件に対して横スクロールが出なかった。 |

接続判定が横取りあり・Options+ 動作中・前回 Active の継続ではない場合、エージェントの起動時刻を調べます。GapSession 作成以前から動いている場合、またはその起動時刻以降に Options+ の設定を一度でも観測した場合は、従来どおり設定済みとして撤退します。設定の観測対象は F と同じく swid 0・5 以外の setCidReporting・setThumbwheelReporting・setSensorDpi です。観測時刻は引き継ぎ後も更新し、リンクやレシーバーの再接続をまたいで保持します。

エージェントが GapSession 作成後に起動し、その起動以降の設定を観測していなければ、前の Options+ の横取りが残った状態と判断して Active にし、肩代わり開始を通知します。hook では G の処理でサムホイールの横取りも解除します。新しい Options+ の設定を観測したら通常どおり引き継ぎます。複数エージェントが見える場合は読み取れた最も新しい起動時刻を使います。起動時刻が不明・取得失敗の場合は、設定の取り合いを避けるため従来どおり撤退します。

| ログの例 | 意味 |
|---|---|
| `Options+起動=19:49:15.123 起動後の設定=なし` | 現地時刻の起動時刻と、その起動以降の設定を観測していないことを示します。GapSession 作成以前から動いていれば、`なし` でも撤退します。 |
| `Options+起動=19:49:15.123 起動後の設定=あり` | その起動以降の設定を観測済みなので、設定済みとして撤退します。 |
| `Options+起動=不明 起動後の設定=なし` | 起動時刻を確認できないため、従来どおり撤退します。 |
| `Options+ は起動後まだ設定していない（前の横取りが残っている）` | 再起動後の空白時間を肩代わりするため Active になった理由です。 |

起動時刻を判定に使わない場合や、起動時刻の取得処理を渡していない場合は、`Options+起動` と `起動後の設定` の 2 項目を出しません。取得失敗は `Options+ の起動時刻を読めません: ...` をアプリのログに 1 回だけ記録します。

H で追加した `// 要確認:` は、起動時刻不明時の観測表示を「なし」として撤退することと、プロセス列挙失敗も含め取得失敗ログをモジュールの生存中に 1 回に限ることの 2 件です。`OptionsRestartTests.cs` で再起動前後・設定の観測・再々起動・不明と例外・通知・残存横取りの解除・既存の Active 継続・境界時刻を検証します。

最初の実機確認では、PartsTray を起動したまま Options+ のエージェントを停止・再起動し、再接続時に上記の未設定理由で肩代わりが始まることを確認してください。hook の解除完了ログとボタン・横スクロールの動作を確認し、その後の Options+ 設定開始で引き継ぎ、二重操作やスクロール停止がないことを確かめます。

## 横スクロールのバネの動き（指示書 I）

11/19 に Google スプレッドシート（列幅は一律 100）で、肩代わり中と Options+ を比べました。

| | 1 回あたりの回転 | 進んだ列 |
|---|---|---|
| 肩代わり中（`speedPercent` 50） | 0.90〜1.05 回転 | A → J〜K |
| Options+ | 0.91〜1.00 回転 | A → S〜U |
| 肩代わり中（`speedPercent` 100） | 約 1 回転 | ほんの少し少ない程度 |

量のほかに、動き方も違いました。Options+ は、一度に多く回すと速く動きます（進む量は同じ）。また、動き始めと止まる前に減速します。

- `thumbWheel.smoothMode`：`linear`（既定）は指示書 E の均等割りです。`spring` は、送った量の合計を、受け取った量の合計へ臨界減衰のバネで近づけます。式は Unity の `SmoothDamp` と同じです。
  - 動き始めは速さ 0 から加速し、目標に近づくと減速します。
  - 目標との差が大きいほど速く動きます。最後は受け取った量をちょうど送り切るので、量は変わりません。
  - 逆向きに回したときは、前の向きの残りを捨てます。
  - 最後に受け取ってから `springMs` の 10 倍たったら、残りを送り切って止まります。
- `thumbWheel.springMs`：バネの時間（10〜500 ms、既定 50）。送る間隔は `smoothIntervalMs` を使います。`smoothMs` が 0 のときは、方式に関係なく分けずにすぐ送ります。
- `speedPercent` の上限を 100 から 300 にしました。
- 実機で合わせるときの目安：動き出しが遅すぎるなら `springMs` を小さくします。止まり方が急なら大きくします。50 ms のとき、本来の 1 段（`speedPercent` 100 で 120）は約 200 ms かけて送られます。

本体（`WheelSpring.cs`、設定、GapSession の切り替え）は Codex が書きました。Codex が使用量の上限で止まったため、テスト（`WheelSpringTests.cs`、19 件）と README は Claude が書きました。

## オウム・CPU 使用率・温度・メモリのアイコン（指示書 J・L）

モニターは次の4つのアイコンで表示します。既存の本体アイコンを温度表示に使い、CPU使用率とメモリを独立させました。電池アイコンの描き方は変えていません。

| アイコン | 中身 | 数字の色 |
|---|---|---|
| オウム | CPU使用率に合わせて速く動く虹色のオウム。既定は数字なしで全面に絵を表示 | ― |
| CPU使用率 | 大きな数字1つ | 水色 `#64D2FF` |
| 温度（本体） | 大きな数字1つ。ACPIの温度、またはCore Tempの有効な全コアの平均 | 赤 `#FF3B30` |
| メモリ | 大きな使用率の数字1つ | 白 `#FFFFFF` |

温度の既定はWindowsのACPIです（Core Temp不要、温度の読み取りは1秒ごと）。複数区域がある場合は最も高い温度を使います。`monitor.tempMemory.source` を `coretemp` にすると、動作中のCore Tempの共有メモリから平均と最高温度を取得します。温度が取れないときは `--`、メモリが取れないときも `--` です。

Core Tempを使う場合は共有メモリを有効にし、Core Temp側のトレイ表示を必要に応じて消してください。`CoreTempMappingObjectEx`、次に `Global\CoreTempMappingObjectEx` を読み取り専用で試し、各周期で閉じます。Core Tempを終了すると温度なしになり、再起動後は次の取得周期で再接続します。

既存の `config.json` の最上位にある `monitor` の設定例です。以下は `digitStyle` をユーザー指定の `thin` にしています（省略時の既定は従来どおり `wide`）。ほかは既定値です。古い設定ファイルに `cpu` や `split` がなくても新しい既定値を使い、明示した `parrot.cpuText` は保持します。

```json
{
  "monitor": {
    "enabled": true,
    "digitStyle": "thin",
    "sampleIntervalMs": 200,
    "parrot": { "enabled": true, "cpuText": "none", "stretch": true, "widenPx": 1, "rainbow": true, "cpuTextColor": "#FFFFFF" },
    "cpu": { "enabled": true, "color": "#64D2FF" },
    "tempMemory": { "enabled": true, "split": true, "source": "acpi", "tempColor": "#FF3B30", "memoryColor": "#FFFFFF" }
  }
}
```

| 設定（`monitor.` 以下） | 意味 |
|---|---|
| `enabled` | falseでオウム・CPU・メモリを消し、本体は標準アプリアイコンと状態文に戻す |
| `sampleIntervalMs` | CPU・メモリなどの取得周期。100〜5000ms、既定200ms。ACPI温度は1秒ごと |
| `digitStyle` | `thin`＝Tahomaをにじませず描く。単独の数字は「88」が収まる最大サイズ。`wide`（既定）＝点の文字を横に伸ばす。単独の数字は20pxなら高さ9 |
| `parrot.enabled` | オウムの表示・非表示 |
| `parrot.cpuText` | 既定は `none`（数字なし、絵を全面に表示）。`bottom`＝数字を下、`top`＝上。従来の数字付き表示も使用可能 |
| `parrot.stretch` | 既定 true。絵が横長（296×223）で正方形のアイコンでは 20×15 にしかならないので、縦にだけ伸ばして枠いっぱい（20×20）にする（11/20 ユーザーの指定）。左右を切ると、左右に振る頭がコマによって切れるため横幅はそのまま。数字を添えて枠が低いときは縦横比のまま。false で縦横比を保つ |
| `parrot.widenPx` | 既定 1。横も左右それぞれこのドット数だけ伸ばす（20px なら幅 22 で描き、はみ出た両端は切れる。11/20 ユーザーの指定）。各コマの絵は全コマの範囲より狭いので、切れるのは頭を一番左右に振ったコマの端だけ。0〜5 |
| `parrot.rainbow` | RunCat365の影絵にだけ適用。true＝虹色、false＝テーマの白／黒。`partyparrot.gif` は元の虹色を使う |
| `parrot.cpuTextColor` | オウムに添える数字の色（`#RRGGBB`）、既定は白 |
| `cpu.enabled` / `cpu.color` | 独立したCPUアイコンの表示と色。既定true／水色 `#64D2FF` |
| `tempMemory.enabled` | falseで温度を標準アプリアイコンへ戻し、メモリを非表示にする。オウム・CPUは独立して表示可能 |
| `tempMemory.split` | 既定true。温度とメモリを別々の大きな数字にする。falseで本体を従来の2段にし、独立メモリを消す |
| `tempMemory.source` | `acpi`（既定）または `coretemp` |
| `tempMemory.tempColor` / `tempMemory.memoryColor` | 温度／メモリの色（`#RRGGBB`）。既定は赤／白。しきい値では色を変えない |

従来の2アイコン構成（オウムの下にCPU、温度とメモリは2段）に戻すには、既存の `monitor` の該当項目を次のように変更します。他の設定は残してください。

```json
{
  "monitor": {
    "cpu": { "enabled": false },
    "parrot": { "cpuText": "bottom" },
    "tempMemory": { "split": false }
  }
}
```

単独の数字は縦横とも中央に置きます。`thin` は「88」の点がアイコンに収まる最大の文字サイズを0.25px刻みで選び、大きさごとにキャッシュします。1桁・2桁・`--` は同じ文字サイズです。3桁はそのまま入れば表示し、入らなければ一辺×2/3pxまで縮め、それでも入らないときだけ `99` にします。ツールチップは実際の値を表示します。**11/20 Claude のレビューで修正**：「88」だけで選ぶと20pxで `basePx = 20.5`（「88」は幅20）になりますが、「49」は「4」の左の出っ張りで幅21になり、アイコンの外に点を打とうとして起動時に落ちました。Tahomaの数字は送り幅が同じなので、「インクが一番左から始まる数字」＋「一番右で終わる数字」の2桁が収まる大きさを選ぶように直しました（20pxで `basePx = 19.5`、「88」は幅19・高さ14、0〜100のすべてが幅20以内。16pxで15.5、24pxで22.5）。描く側も、万一はみ出した点は描かないようにしました。従来の2段・オウム・電池に重ねる数字は小さいままです（20px・thinなら高さ9、wideのオウム・電池は高さ7）。

オウムは配置済みの `Assets/parrot/partyparrot.gif`（10コマ）を優先します。黒いふちと目を透明にしてから縮め、縮めたコマは大きさが変わるまで使い回します。GIFが無ければRunCat365の影絵、それも使えなければ丸を表示します。影絵を配布する場合は `parrot_0.png`〜`parrot_9.png` とライセンス文書（Apache License 2.0）を同じ `Assets/parrot/` に置きます。素材の再読込には再起動が必要です。今回素材のダウンロード・追加はしていません。

CPU・メモリ・単独温度は値・色・サイズ・書体が同じならアイコンを差し替えません。タスクバーや隠れたアイコンの小窓でボタンを押している間と、離してから0.6秒はアイコンとツールチップを更新しません。設定変更による非表示化も並べ替えが終わってから反映します。通常の設定再読込は約1秒ごとで、不正な値は拒否して前の設定を維持します。

本体の左クリックによる設定表示、中クリックによるジェスチャー一時停止、右クリックメニュー、バルーン通知は従来どおりです。オウム・CPU・メモリの右クリックは同じメニューを開き、左・中クリックは何もしません。CPUのツールチップは `CPU 32%`、メモリは `メモリ 49%（7.8/16.0 GB）` の形式です。本体（温度）は温度だけを表示します（2段表示のときはメモリも）。PartsTray の状態文（`PartsTray: 肩代わり中` など）は、11/20 のユーザーの指定でマウスの電池アイコンのツールチップの2行目に移しました（`monitor.tempMemory.enabled` が false のときは本体にも出します。右クリックメニューの先頭にも従来どおり出ます）。GBは1024³バイト換算、小数1桁、ツールチップは最大127文字です。起動直後のCPUは比較用の値がないため0%で、次の周期から差分を表示します。

## 周辺機器ごとの電池アイコン（指示書 K）

電池残量を取得できた機器ごとに、通知領域へアイコンを1つ追加します。機器が眠ったり切断されたりしてもアイコンは消さず、最後の値を薄く表示します。右クリックでは既存の PartsTray のメニューが開きます。

対象機器と読み取り方法は次のとおりです。番号や機能番号は実機記録の値であり、コードでは固定せず探索します。同じ方式で読めるほかの機器も対象です。

| 機器 | つながり方 | 読み方 |
|---|---|---|

**読み取りの制限と既存機能との分離**

- ロジクールの照会は既存の `Transport` と HID の送信口を共有し、送信をロックで直列化します。電池用は長い形式（0x11）・**swid 7**、つなぎ役は従来どおり **swid 5** です。
- 電池用に許可するのは ROOT の ping、getFeature（0x1004・0x1000・0x0005）、機器名・種類、電池残量の読み取りだけです。送信直前に許可リストを検査し、書き込み関数を拒否します。0x1004 が無い機器では 0x1000 を使います。
- レシーバーを開いたときは番号1〜6を1つずつ ping し、応答があった機器を探索します。接続通知でも探索を開始し、既知の機器では残量だけを取得します。電池の未完了要求は全機器を通じて1つです。1秒の無応答で最大2回再送し、それでも応答がなければ、その番号は次の接続まで待ちます。
- 受信は `GapSession.Receive` の後に電池追跡器へ渡します。電池は独立したロックと1秒周期のタイマーを使用し、つなぎ役の状態管理は変更しません。電池の応答は swid 7、自発通知は swid 0 の fn0 だけを使い、Options+ の照会応答は使いません。読み取り応答でつなぎ役が引き継ぎに入らないことをテストしています。
- Bluetooth は SetupAPI で存在する機器を列挙し、上表の BYTE プロパティを持つ機器だけを背景スレッドで読みます。名前の末尾の ` Hands-Free AG`・` Hands-Free`・` Avrcp Transport` は取り除きます。充電状態は取得できないため不明とします。**11/20 に直した**：最初は `CM_Get_DevNode_Status` の `DN_STARTED` で接続を判断していましたが、実機では WH-1000XM6 の「Hands-Free AG」はペアリング済みなら切断中も `DN_STARTED` のままで、電池の値も最後の値（11/17 の 56%）が残り、切断中のヘッドホンが表示され続けました。今は、同じ入れ物の ID（`DEVPKEY_Device_ContainerId`）を持つ音の出入り口（`SWD\MMDEVAPI\…`）または HID が「存在する」ときだけ接続中とします（これらは接続中だけ現れる。切断中に現れないことは確認済み、接続時に現れることは未確認）。入れ物の ID が読めない機器だけ `DN_STARTED` で判断します。
- BatteryHub のコードは使用していません。追加パッケージもありません。

**設定**

`config.json` の最上位に `battery` を追加できます。省略した場合も以下の既定値で動作します。

```json
{
  "battery": {
    "enabled": true,
    "logitech": true,
    "bluetooth": true,
    "lowWarn": 20,
    "lowHot": 10,
    "hidden": [],
    "refreshMinutes": 10,
    "bluetoothPollSeconds": 60
  }
}
```

| 設定 | 意味・範囲 |
|---|---|
| `enabled` | 電池機能全体の有効・無効 |
| `logitech` / `bluetooth` | 読み取り方式ごとの有効・無効 |
| `lowWarn` / `lowHot` | 以下なら橙／赤。どちらも1〜100、`lowHot < lowWarn` |
| `hidden` | 非表示にする機器名の配列。大文字・小文字も含めて完全一致 |
| `refreshMinutes` | 接続中のロジクール機器への残量再照会間隔。1〜120分 |
| `bluetoothPollSeconds` | Bluetooth プロパティの読み直し間隔。10〜600秒 |

例えば `"hidden": ["WH-1000XM6"]` と保存すると、設定の再読込でそのアイコンを消します。配列から名前を外すと再表示します。切断や同じ値の取得ではアイコンを作り直さず、作成順を維持します。明示的な非表示・無効化では破棄するため、再表示したアイコンの位置は Windows の管理に従います。

**表示と最初の実機確認**

**11/19 の見た目の変更（ユーザーの指定、見本 A）**：機器の絵は点の絵をやめ、Windows 11 の「Segoe Fluent Icons」の記号（無ければ「Segoe MDL2 Assets」）を色付きで描きます。色はマウスが水色（#5AC8FA）、キーボードが黄色（#FFCC00）、ヘッドホンが紫（#AF52DE）、その他が灰色です。残量の数字は従来の大きさ（20px・wide で高さ 7、thin で高さ 9）で、絵の下の方に重ねます。数字のまわり 1 ドットは絵を消して、数字を読みやすくします。絵の高さは `battery.pictureHeight`（20px のアイコンでのドット数、8〜20、既定 15）で変えられます。20 で全面、12 で数字と上下に分かれる形になります。

同じ日の 2 回目の調整：絵は一辺 `pictureHeight` の正方形に収めます（横長のキーボードだけ大きく見えないように）。絵はベタ塗りにし、外に接していない内側の線（キーボードのキー、マウスの真ん中の線）は穴として残します（`PictureMask.Solid`）。ヘッドホンは Windows の記号だと線が細すぎて見えないため、太い弧と塗った耳あてを自分で描きます。残量の数字の色は、20% 以下が黄色（#FFCC00、前は橙）、10% 以下が赤です。充電中は残量に関係なく緑です。

（以前の形）上段はマウス・キーボード・ヘッドホン・その他の形、下段は残量の数字でした。100は3桁が入るときはそのまま表示します。値が無ければ描画上は `--` ですが、まだ一度も残量を取得できていない機器のアイコンは作りません。

**11/20 の見た目（今の形。ユーザーと見本を何度も見比べて決めた）**：iPhone の電池ウィジェット風にしました。

- 輪：残量の分だけ色の輪を描く（太さ 2 ドット、アイコンの端まで）。減った部分は描かない。輪は 4 倍で描いて滑らかに縮め、黒い背景で縁がくすまないよう色を明るくする（緑は #34C759 → 色合いそのまま一番明るく）
- 輪の色は残量だけで決める：普段は緑、`lowWarn`（20%）以下はオレンジ（#FF9500）、`lowHot`（10%）以下は赤（#FF3B30）。充電中かどうかでは変えない（`BatteryMath.RingColor`）
- 充電中・ゆっくり充電中・充電完了（ケーブルがつながったまま満タン）は、右下に黄色（#FFD60A）の稲妻を出す。まわり 1 ドットは透明にして輪や絵と離す（`BatteryMath.ShowsBolt`）。黄色の稲妻とかぶらないよう、20% 以下の輪を黄色からオレンジに変えた。WH-1000XM6 は Windows から % しか読めないので、稲妻はロジクールの機器だけ

- 数字はアイコンに描かず、ツールチップに出す。マウスのツールチップの 2 行目には PartsTray の状態を出す

（11/19 までの色）充電中は緑（#34C759）、それ以外は `lowHot` 以下で赤、`lowWarn` 以下で橙、通常はテーマに応じた白／黒です。切断中は絵も数字もアルファ40%です。レベルだけから得た値は危険5%・低20%・良50%・満90%の概算で、数字に記号を足さずツールチップにだけ「（概算）」と表示します。例：`MX Master 4 85%（充電中）`、`MX Master 4 85%（切断中・22:31 時点）`。

Windows 11 では新しいアイコンが最初は「隠れたアイコン」に入るため、タスクバーの設定で各アイコンの表示をオンにしてください。まず3台の名前・形・残量を確認し、充電開始時の緑表示、スリープ・電源オフ時の薄い表示、再接続時の復帰を確認してください。WH-1000XM6 は、切断中に消えることは 11/20 に確認済みです。つないだときに出てくることを確認してください。併せて `hidden` の反映、右クリックメニュー、明暗テーマと表示倍率、Options+ への通常の引き継ぎが維持されることを確認してください。

## 切り替えの通知と二重動作の確認（指示書 C）

肩代わりを開始すると「肩代わりを開始しました（接続から 0.18 秒）」、Active から Options+ に引き継ぐと「Options+ に引き継ぎました（肩代わり 13.42 秒）」の形式で通知します。秒数はそれぞれ接続から開始まで、開始から引き継ぎまでの実測値です。同じ文を `通知: ...` としてログにも残します。起動時から Options+ が設定済みの場合や、接続判定中に Options+ の設定開始を検出した場合は通知しません。

通知は既定で有効です。既存の `config.json` の `gapFiller` 内に `"notifyOnSwitch": false` を追加すると、設定再読込後は次の接続を待たずに通知と `通知:` のログを停止します。ほかの確認用ログは継続します。項目がない既存ファイルは書き換えず、true として読み込みます。Windows の「通知」の設定や「応答不可（集中モード）」が有効だと、通知が表示されないことがあります。

確認用ログは次の意味です。一時停止中の入力は観察しません。

| ログの例 | 意味 |
|---|---|
| `ボタン CID=0053 押下: PartsTray は実行しない（Options+ に引き継ぎ済み） 設定=Keys Ctrl+V` | 設定のあるボタンの新しい押下を受信しましたが、PartsTray は実行していません。押したままの同じ通知は重複記録せず、離して押し直すと再記録します。接続判定中は理由が「接続判定中」になります。 |
| `サムホイール回転を検出: PartsTray は送信しない（Options+ に引き継ぎ済み）※このリンクでは 1 回だけ記録` | 回転量が 0 でない通知を受信しましたが、PartsTray は水平スクロールを送信していません。接続判定中も含め、1 リンクにつき 1 行だけ記録します。指が触れただけの回転 0 や不完全な通知では記録せず、記録済みの印も立てません。再リンクすると再び記録できます。 |
| `未実行のボタン操作を破棄 CID=0053 設定=Keys Ctrl+V` | 実行待ちのボタン操作が、実行前に破棄されました。Options+ が処理したかどうかはこの行だけでは分かりません。 |
| `未送信のサムホイール 3 件を破棄` | `divert` 方式の実行待ちサムホイール送信をまとめて破棄しました。ボタン・ホイールとも破棄の理由は直後の状態遷移の行で確認します。`hook` のキューは引き継ぎ後も送るため対象外です。 |

最初に、Options+ への引き継ぎ通知の直後に、保存不要のメモ帳で戻るボタンによる貼り付けを試してください。「PartsTray は実行しない」の行が押下ごとに 1 行出て、画面で貼り付けが 1 回だけ起きていれば、Options+ だけが処理しています。肩代わり中から押し続けたボタンは、引き継ぎ後も新しい押下として記録しません。いったん離して押し直して確認します。サムホイールの「送信しない」ログは HID の回転通知についての記録です。`hook` では、上記の橋渡し終了まで Windows の横スクロールの送り直しが続きます。

`app/publish` のフォルダで PowerShell を開くと、次の例でログをリアルタイムに確認できます。


C の追加分は `PartsTray.Tests/SwitchObservationTests.cs` で検証します。C レビュー 1 では、接続判定中・引き継ぎ後のそれぞれについて、回転 0 や短い通知では記録せず、その後の正・負の回転で 1 行だけ記録するテストを追加しました。

`ReplayTests.cs` の入力は `PartsTray.Tests/Fixtures/` 内の固定コピーです。記録中の `logs/` へのリンクは使いません。`sniff_20261118_230321.log` は元ログの先頭から `===== 11:26:18 レシーバーが外されました =====` の直前までの **1166 行**、`sniff_20261118_224803.log` は元ログ全体の **156 行**です。境界行を検索して範囲を確認し、どちらも UTF-8（BOM なし）・CRLF のまま保存しました。元の `logs/` は変更していません。両方の入力でキー・ホイール送信が全期間ゼロであることと、非 Active 時の入力増分がゼロであることを検証します。

## 判断事項と制約

- **起動時の機器識別**：レビューで確定した規則に従い、番号 1〜6 へ ping を送り、応答した未知の機器には ROOT.getFeature(0x0005) と DEVICE_NAME の長さ・部分名を読む照会だけを許可します。名前が `MX Master 4` と完全一致した番号を WPID=B042 として扱います。番号 2 を決め打ちしません。
- **接続ごとの判定**：機能探索後に中ボタンの横取り状態を読み、その時点の Options+ プロセスの有無で Active / Retreated を決めます。同じアプリ実行中、同じレシーバー・機器番号の直前のセッションが Active のまま終わった場合は、残っている ON を自分の設定とみなして再開します。一時停止・引き継ぎ後や別レシーバー・別番号では、この例外を適用しません。横取り ON・Options+ 動作中でこの継続例外がない場合は、GapSession 作成後に起動したエージェントの設定をその起動以降に観測していなければ肩代わりし、作成以前から動作・起動以降の設定を観測済み・起動時刻不明の場合は撤退します（指示書 H）。
- **設定更新**：安全のため DPI・割り当て・横取り設定は接続開始時に固定し、次回接続で適用します。ホイール速度・方向は即時反映、enabled=false は即時停止、true に戻しても次の接続まで書き込みません。WPID と PartsTray 自身の swid（5）は変更を拒否します。無効な設定は以前の値を維持しログへ記録します。初回の設定不正時は停止状態で起動します。
- **再送**：初回送信＋最大 3 回の再送。Busy は 50 ms 後、無応答は 1 秒後。初期適用の失敗後は Active のまま次の外部通知/応答を待ち、未完了ステップから再開します。
- **受信と撤退**：受信処理が撤退を確定した後はボタン入力・横取り方式の入力送出・通常書込みを行いません。フック方式の橋渡しは上記の終了条件まで継続し、受け取り済みのキューも送ります。既に OS に提出した I/O や Options+ が実際に書いた時刻と応答が配信される時刻との差は取り消せません。実機での二重実行確認は必須です。
- **サムホイール**：既定はフック方式です。`divert` の `setReporting(1,1)` と回転通知の方向・単位、フック方式での反転符号は実機で最終確認します。読み戻しは 1 バイト目が 1、2 バイト目の bit0 が 1 なら正常で、指の接触を示す bit1 は不一致としません。
- **対象**：同一 Container ID の short/long を持つ最初の Bolt 1 台のみ。つなぎ役は MX Keys S 等に起動時の ping と上記の識別用照会以外を送りません。指示書Kの電池機能は独立して swid 7 の電池・名前・種類の読み取りを行います。受信の他機器通知でマウスの機能設定を変更しません。

## ジェスチャーの使い方と設定

右ボタンを押して動かし、離すと実行します。←＝戻る、→＝進む、↑↓＝更新、↓→＝閉じる、↓←＝最小化です。対象は押し始めた場所のトップレベルウィンドウです。「閉じる」は登録ブラウザと Explorer では Ctrl+W、それ以外ではウィンドウを閉じます。

最初のストロークが成立してから軌跡を表示し、押した場所までさかのぼって描きます。登録と完全一致している間は緑、それ以外は赤です。色が変わると軌跡全体を描き直します。右ボタンを離すと消えます。未登録の形でも右クリックメニューは出しません。動かさずに離せば普通の右クリック、ストロークがないまま 1 秒たてば普通の右ドラッグになります。

ジェスチャー中の左クリックはコマンドの連続実行です。一度実行した後は右解放時に追加実行しません。1 秒静止すると方向とコマンド名を表示します。

初回作成される `config.json` には、既存の `gapFiller` に加えて次のルート項目が入ります。以前の設定ファイルで項目がない場合は同じ既定値で動作します。調整する場合は `gapFiller` を残して以下の項目を追加してください。保存後、約 1 秒で反映し、進行中の判定は安全に終了します。未対応のコマンドや不正な色・値は拒否し、以前の設定を維持します。

```json
{
  "gesture": {
    "enabled": true,
    "strokeDistancePx": 10,
    "startTimeoutMs": 1000,
    "tooltipDelayMs": 1000,
    "rapidFire": true,
    "trail": { "enabled": true, "widthPx": 3, "validColor": "#00FF00", "invalidColor": "#FF0000" },
    "gestures": { "L": "Back", "R": "Forward", "UD": "Refresh", "DR": "Close", "DL": "Minimize" },
    "browserProcesses": ["chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "vivaldi.exe", "opera.exe"],
    "excludedProcesses": [],
    "explorerSkipSelectedItems": true
  },
  "titleBar": {
    "shiftClick": "ToggleTopMost",
    "ctrlClick": "OpenExecutableFolder",
    "middleClick": "CloseWindow",
    "minimizeButtonRightClick": "MinimizeToTray"
  },
  "wheel": { "fastScrollOnScrollBar": true, "fastScrollMultiplier": 5, "focusUnderCursor": true },
  "moveDisabledWindows": true
}
```

`gesture.enabled` はジェスチャーだけの有効・無効です。`titleBar` の各値を `"None"` にすると個別に停止できます。B の機能全体を止めるにはトレイメニューの「ジェスチャーを一時停止」、またはトレイアイコンの中央クリックを使います。「つなぎ役を一時停止」は独立しています。左シングルクリックで設定を開き、右クリックでメニュー、ダブルクリックは何もしません。シングルクリックはダブルクリック判定時間だけ待ちます。

**Kazaguru.exe が動作中は B の機能全体を自動停止**し、アプリ実行中に一度だけ通知します。5 秒ごとに確認し、かざぐるを終了すると再開します。HID のつなぎ役には影響しません。

フックからファイル書き込み・UIA・SendMessage・描画は呼びません。キーやウィンドウ操作が遅れても、ボタン・ホイールの送り直し専用ワーカーを塞がない構成です。保留した解放は押下の後に送り、送り直しの完了通知を受けるまでは実際の解放も保留します。2 秒で未決定の判定は返却し、遅れて届いた結果では実行しません。

同じボタンの新しい押下が来たのに古い記録が残っていた場合は、解放の取りこぼしとして古い判定を破棄し、ワーカー経由で警告します。古いコマンドや押下は実行・再送しません。ただし押下の送り直しがまだ未完了なら、その後ろへ解放を 1 回追加して釣り合わせます。Raw Input 生存監視でフックを付け直すときは `HookLost()` で全記録を破棄し、送り直しもコマンドも発行しません。無効ウィンドウのドラッグ中もカーソル移動は素通しとし、押下位置からの累積移動量でウィンドウを移動します。

通常のホイールは Windows に任せます。高速スクロールだけ、同じ物理座標・100 ms 以内の肯定キャッシュがあるときに横取りし、SendInput で倍率を掛けて返します。失敗時は 60 秒横取りを停止します。判定はカーソル下の子ウィンドウを対象にし、`WS_VSCROLL` がある場合だけ `WM_NCHITTEST` を送ります。`ScrollBar` クラスで縦向きのコントロールにも対応します。ブラウザや WinUI など標準スクロールバーを持たないウィンドウには、このメッセージを送りません。

最後の移動またはホイールから 3 秒間は、静止中でも 50 ms 間隔を目安にキャッシュを再判定します（タイマーの配送により遅れる場合があります）。移動・ホイール・静止更新を通じ、判定依頼の間隔は最低 30 ms です。3 秒を過ぎると依頼を止めます。長時間静止後の最初のホイールは通常のスクロールとして通し、同時に判定を依頼します。判定が返った後のノッチから高速スクロールになります。

フォーカス移動は UI Automation を使わず、前面ウィンドウ内の **HWND を持つ枠**だけを対象にします。スクロールバーとヘッダーは親を対象にし、トップレベルだけのアプリ、非表示・無効な枠、既にその枠や子孫にフォーカスがある場合は何もしません。専用スレッドで一時的に入力を共有し、`SetFocus` の後は `finally` で共有を解除します。実行中の追加依頼は捨て、フックや右クリックの判定スレッドは一切待たせません。同じ内容の失敗ログは連続出力しません。相手の GUI が停止して既に発行した API が戻らない場合でも、依頼やスレッドを増やしません。

UIA は Explorer の選択中項目の判定だけに使用します。起動時に選択判定と同じ MTA スレッドへ `AutomationElement.RootElement` の取得を一度投げ、待たずに暖機します。選択判定の待機上限は従来どおり 50 ms です。暖機やプロバイダーがまだ応答しない場合はジェスチャーを許可するため、起動直後の実機確認も必要です。

軌跡は入力キューの通知で描画し、同色のままなら増えた線分だけを描きます。色変更時だけ全経路を再描画します。モニターごとの原点を引いた物理ピクセル座標を使い、DPI 倍率は掛けません。manifest と WinForms の DPI 設定はともに PerMonitorV2 です。指示書 B が manifest を指定しているため、同じ設定の二重指定を警告する WFO0003 だけを明示的に抑制しています。

収納一覧は exe の隣の `state/hidden_windows.json` です。隠す前に書き込み、起動時と通常終了時に再表示します。HWND の再利用に備えて PID と開始時刻も比較します。復元できないものは記録を残します。「隠したウィンドウをすべて戻す」でも再表示できます。書き込み不可・壊れた復元一覧がある場合は、新たにウィンドウを隠しません。

## B の判断事項・未確認事項

B のコードの `// 要確認:` は次の 6 件です（今回追加したものは項目 6 の 1 件）。

1. `GestureEngine.cs`：連続実行に一度でもコマンドを発行した場合、右解放時には実行しない。
2. `GestureEngine.cs`：45 度で両軸が同じ移動量なら横方向を採用する。
3. `WindowsGestureServices.cs`：Shift+Ctrl+左クリックは Shift を優先する。
4. `WindowsGestureServices.cs`：Explorer の UIA が文字・アイコンの領域を公開しない場合は余白扱いとしてジェスチャーを許可する。実際の Windows 11 の表示形式で確認が必要。
5. `HiddenWindowManager.cs`：収納アイコンの「閉じる」は、保存確認が見えなくならないよう先に再表示してから閉じる。
6. `GestureEngine.cs`：取りこぼした右押下に従属する未確定の連続実行も破棄し、その左ボタンがまだ保持中なら解放だけを消費する。失われた古いジェスチャーのコマンドを後から実行しないため。

A から継続する `// 要確認:` は、接続中の HID 設定変更を次回接続まで延期すること、サムホイール通知の先頭 int16 BE の方向・単位、setReporting(1,1) の意味の 3 件です。directionSign のコメントは D で「1 = Options+ の反転オンと同じ向き、-1 = その逆」に更新しました。error20 の Python 版との不一致に関するコメントと記述は削除済みです。

実機を起動していないため、フック時間・描画の追従性・混在 DPI・UIA の実際の応答・管理者ウィンドウへの操作・全画面アプリ上の表示・長期間の安定性は未測定です。通常のデスクトップ上の topmost オーバーレイであり、セキュアデスクトップや排他的全画面での表示は保証しません。フック時間は実行時に計測し、5 ms 超過をワーカーから警告、終了時に `フック処理時間 count=… average=…ms max=…ms` をログに残します。

## B の手動確認（レビュー後にユーザーが実施）

1. **かざぐるマウスを終了してから**、上記の発行手順で作った PartsTray を起動します。共存中は B の機能が自動停止し、終了から最大約 5 秒で再開することも別途確認します。まず通常の右クリックが届き、トレイから一時停止・終了できることを確認してください。
2. 保存不要のブラウザタブで ←、→、↑↓、↓→、↓← を試します。戻る・進む・更新・タブを閉じる・最小化になることを確認します。背景にある対象でも、キーが別の前面ウィンドウへ送られないことを確認します。
3. 右ドラッグで大きな円や文字を描きます。幅 3 px の丸い線が遅れずに付き、有効な形は全体が緑、未登録の形は全体が赤になることを確認します。未登録の形で離すと即座に消え、操作も右クリックメニューも出ないことを確認します。数万点になる長いらくがきでも遅れが増えないか確認します。
4. 2 台以上のモニターをまたいで描き、負の画面座標や 100%／150% などの混在 DPI でも線がつながり、位置・太さが変わらないことを確認します。全画面ウィンドウ上でも確認します。
5. 普通の右クリックでメニューが出ること、1 秒静止してから右ドラッグできることを確認します。Explorer で選択済みのファイルを右ドラッグし、コピー・移動メニューが使えることを確認します。起動直後にも試し、UIA 暖機後の選択判定を確認します。詳細表示の文字右側の余白、未選択項目、背景ではジェスチャーが始まることも確認します。
6. ← のまま左クリックを 3 回すると戻るが 3 回だけ実行され、右ボタンを離しても追加実行されないことを確認します。1 秒静止時のツールチップと、動かしたときの消去も確認します。
7. タイトルバーの Shift+左クリック＝最前面切り替え、Ctrl+左クリック＝実行ファイルを選択した Explorer、中央クリック＝閉じるを確認します。最小化ボタンの右クリックで通知アイコン化し、アイコンの左クリック・メニュー・全件復元で戻せることを確認します。MX Master 4 の中ボタンが DPI 切り替えに割り当てられている間は通常の中央クリックが届かないため、中央クリックを送れる別のマウス等で確認してください。A の割り当ては変更していません。
8. 保存不要のテスト用ウィンドウを収納し、PartsTray の通常終了で戻ることを確認します。異常終了からの復元を確認する場合は、手動で PartsTray を終了させて再起動し、ウィンドウが戻ることを確認します。復元一覧はこの確認が済むまで消さないでください。
9. **「システム情報」（msinfo32）の左のツリー・右の一覧**、または **コントロール パネル →「プログラムと機能」の一覧**の標準の縦スクロールバー上で、ホイールが 5 倍になることを確認します。バー上で約 1 秒静止してから回しても高速になること、3 秒以上静止後は最初のノッチが通常で、その判定後のノッチから高速になることを確認します。**ブラウザ、新しいメモ帳、Explorer の一覧は標準スクロールバーではないため高速スクロールの対象外**です。通常のスクロールは維持されることを確認します。フォーカス移動は、msinfo32 の左ツリーにフォーカスを置き、右の一覧でホイールを回すと右の枠へ移ることを確認します。ブラウザではリンクやボタンにフォーカス枠が出ないこと、背景アプリが前面に出ないことも確認します。
10. モーダルダイアログの背後にある無効な親ウィンドウの、見えているタイトルバー上で約 1 秒静止し、左ドラッグします。カーソルが動き続け、ウィンドウも押下位置からの累積の移動量に合わせて滑らかに移動し、元の位置の近くで震えないことを確認します。通常の左ドラッグには遅延がないことも確認します。
11. トレイの左・右・中央・ダブルクリック、多重起動による設定表示を確認します。B の一時停止中も A のつなぎ役が動作することを確認します。
12. 数日使ってスクロールが止まらないか確認します。問題が起きたらログの「フックを付け直した」「ボタン解放の取りこぼし」「5ms」「SendInput」「60秒停止」「ボタン判定が2秒未確定」を確認し、通常終了後のフック平均・最大時間も確認します。復旧後の普通の右クリックで古いジェスチャーが実行されず、ボタンが押されたままにならないことも確認します。既存の A の二重実行確認も合わせて行ってください。
